# B9 / HD-2D 属性の音 26本

2026-11-08 / `codex/assets-b9-20261108`

10属性の「予備動作」「当たり」20本と、敵の当たり6本です。CC0の録音を切り出し、速度・帯域・包絡・重ね合わせで編集しました。AI音生成、BGM、ゲームコードの変更はありません。

**重要: 音声を聴覚で評価できる機能がこの制作環境にはないため、制作担当・独立QA担当とも試聴していません。** 数値検査は済みですが、聴感や実ゲーム音量の合格を意味しません。原音・加工前マスター・完成音を比較できる `listen.html` を付けました。これを理由に確認待ちで作業を止めることはしません。

## 規格

- 実装用: `Audio/sfx/hd2d_<属性>_{onset,contact}.wav` と `hd2d_enemy_<形>_contact.wav`。48,000 Hz・モノ・PCM16・非ループ。
- `raw_masters/`: 音を重ねた後、最終音量調整と16bit化を行う前のfloat32マスター。**未加工の録音そのものではありません。**
- `source_excerpts/`: 出典付きの原音。BigSoundBankは元録音の指定フレームを無加工で切り出し、元のサンプルレート・PCMビット深度を保持。Kenneyは原本OGGをそのまま同梱。竹だけは以前のCC0編集音で、元の生録音ではありません。
- 録音全体のURL、原本SHA256、切り出し範囲、作者、ライセンス、各音の加工レシピは `provenance.json` と `manifest.json`。
- `tools/rebuild.py`: 同梱原音だけから26音を再生成。`python3 tools/rebuild.py --out /tmp/b9-rebuilt`。Python・numpy・scipy・ffmpegが必要。出力先以外は書き換えません。同一制作環境で26本のSHA256再現を確認しました。

## 音量と検査

短い予備音に積分LUFSだけを使うと、400ms未満の音では計測値が得られないため、BS.1770のK-weightingによる**最大400ms窓のラウドネス**で比較しています。短音は計測時だけ無音を補います。納品音に計測用の無音は足していません。

- 仮目標: 予備 -32 LUFS-M、当たり -27 LUFS-M。
- true peakは -6 dBTP以下を優先。大きい過渡音を潰さないため、蔦・雷などは目標音量より約1〜2.3 LU低いままです。リミッターで均一に潰していません。
- 4倍オーバーサンプリングのtrue peak、波形ピーク、RMS、DC、クリップ、末端、長さ、ファイル形式、26音の一意性を記録。独立検査は `qa/`。
- 1〜35msの端部フェードでクリックを抑制。予備音は自然な立ち上がりを残し、明確な発音の遅れは約3〜11msです。打撃の主過渡は先頭付近に置き、尾に余韻を残しています。

`listen.html` はZIPを展開して開いてください。外部通信・外部ライブラリ・自動再生はありません。

- 個別プレイヤー: 完成ファイル等倍。原音リンクは**未正規化**で完成音より大きい場合があります。低音量から再生してください。
- `preview/26_sounds_nominal_gain.wav`: 表の順に予備→当たり、最後に敵6音。キー音量 .45/.68 を適用。開始時刻は `cue_times.json`。
- `preview/contact_6hit_120ms_default_master_sfx.wav`: 各属性の当たりを0.12秒間隔で6連。キー音量 .68 と既定Master×SFX=.56を適用。BGMは混ぜていません。

## Claudeへの取り込み

**現在の呼び出しは物理・火の専用音に限定されており、素材とJSONを置くだけでは全26音は鳴りません。** この束はゲームへ自動適用していません。

1. `Audio/sfx/` の26本を `unity/Assets/Resources/Audio/sfx/` へコピー。既存の `hd2d_swing` 等6本やUSFX素材は削除・上書きしない。
2. `audio.fragment.proposed.json` は **追加候補のsfx部分だけ**です。`audio.json` 全体の代替ではありません。BGM表には触れない。
3. 今回のキーは `Hd2dOnset.element.<属性>` / `Hd2dContact.element.<属性>` / `Hd2dContact.enemy.<形>`。現行の `Hd2dOnset.<札>` / `Hd2dContact.<札>` と同じ発音地点から、確定した素材属性・敵styleに対応付けるための**未接続の意味別キー**です。既存の代表札への縮約・専用音許可判定を必要な範囲だけ拡張してください。カード色や名前の文字だけで決めない。
4. 予備は1回のcast/attack開始に1回。当たりは実際の接触時。遠隔は着弾時、多段は実contributionに合わせる。予備と当たりの間隔を音ファイルに焼き込んでいません。
5. 攻撃contactは正のHP損失が確定した時だけ。完全防御は既存の防御音、無効・miss・ゼロ損失には痛打音を鳴らさない。回復contactは**正の回復が確定した時**の別契約で、HP損失条件を適用しない。
6. 新しい音が鳴った場合のみ旧汎用打撃を抑制。音が無ければ旧音へfallback。全体攻撃の既存の音集約を保ち、対象人数ぶん同時に重ねない。実際の6連ヒットは6回の接触として扱う。
7. 回復は新しいHD2D候補であり、ユーザー選定の `HpHealed` のハープを無断で置換しない。必要な回復ルートを明示して接続し、二重再生しない。
8. 新たなGameEvent型名のキーを直接増やさない。現配管では音だけ鳴らして絵の処理を飛ばす場合があります。接続表は `routing.json`。

## 決めたこと

- 敵6名称はbacklogに明記がなかったため、既存の6専用style（牙・爪・突き・打撃・光線・飛び道具）を採用。斬撃fallbackは物理contactで受ける。酸・毒・呪い等の8種とは別。
- 蔦は `vine` と命名。`vegetal` や木の素材を一律に蔦へ振らず、実際に蔦/葉の表現をしている経路だけ対応させる。
- 波形や音色を使い回して長さだけを変えるのではなく、属性ごとに録音の組み合わせ・帯域・音の前後を変えた。
- 長い録音の全体をゲーム素材に大量同梱しない。原本のURLとハッシュ、使った正確な範囲を記録し、必要な原音断片を同梱。加工マスター26本は全て保持。
- 発声・人声・BGM・旋律・他作品の音をサンプリングしていない。
- 日付は依頼された枝名に合わせ20261108。公開範囲はこのhandoffの新規ファイルのみ。
