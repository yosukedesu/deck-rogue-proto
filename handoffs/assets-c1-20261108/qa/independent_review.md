# C1 実寸版・独立 QA

## 判定

**素材単体として納品可。ゲーム統合・GPU・Android の合格ではありません。**

対象は `assets/act2/far_0..2.png` と `assets/act3/far_0..2.png` の 6 枚。幕2の霧は `source/raw/act2/far_2_source_v2.png` 由来の修正版を確認しました。指定 opacity と、基部を地形で隠す条件を README / manifest に明示することを推奨します。再生成を必要とする画面破綻は見つかりませんでした。

## 独立確認した範囲

- 最終 PNG 6 層の実寸コンタクトシート、幕ごとの合成、左右の接続を中央に移したシーム画像を `view_image` で実見。
- 各幕の camera X = -4800, -960, -1, 0, 960, 4571.428571, 8000 の 7 段階を実見。地形の代わりの診断遮蔽は y >= 248。
- 最終 PNG を独立に開き直し、寸法、mode、アルファ、左右端差、端に隣接した濃度変化を再計算。
- `ffprobe` で両 MP4 が 960×270、20 fps、12 秒、240 フレームであることを確認。`ffmpeg -f null` で全フレームをエラーなくデコード。
- 元の候補 6 PNG が、保存された `source/raw/` の同名ファイルとバイト単位で一致することを確認。
- 動画の全時間を人間のように連続視聴したという判定ではなく、段階画像の実見、連番計測、動画デコードの検査です。

## 独立数値検査

- 6/6 が **960×270、RGBA**。
- far0 の 2 枚は全画素 alpha 255。重ねる 4 枚には実際の透明画素があり、全 4 枚の左右最外列 alpha は 0。
- 6/6 で左右最外列の **RGBA 最大差 = 0**。
- 不透明層の端隣接 RGB 変化の平均は幕2 0.546/255、幕3 0.520/255。画像内の列ごとの変化の 95% 点はそれぞれ 1.990/255、0.818/255。継ぎ目の隣だけ極端な縦筋になる傾向は見られない。
- 透明層の上端は全て alpha 0。下端は幕2 far1 と幕3 far1 に alpha 1 の微小残渣があるが、目視で切断線は見えない。幕2 far2 と幕3 far2 の下端は alpha 0。厳密な「全余白が alpha 0」とは表記しない。
- 霧 ON/OFF を独立に合成比較。修正版 opacity 0.18 は最大 RGB 変化 +13/255、最小 -1/255。明るくなる画素 7,536、わずかに暗くなる画素 6。旧版の黒い帯を再発させていない。
- 元候補 6 PNG のバイト保存は 6/6 合格。旧霧も履歴として残っており、最終取り込みは `assets/` のみを選ぶ必要がある。

## 納品条件・未検証事項

1. 推奨 opacity は幕2 `[1, 0.65, 0.18]`、幕3 `[1, 0.55, 0.82]`。PNG へ opacity は焼き込まず、実装側で適用する。
2. 表示順は far0 → far1 → far2 → 3D地形。比較上は y >= 248 を遮蔽した。実ゲームではカメラ移動時も建築の水平な基部が露出しないように配置する。
3. 横反復の素材仕様と、CPU による合成・移動は検査済み。実際の 3D ステージ、照明、キャラクター、UI、GPU、端末性能、Android の見え方は未検証。
4. MP4 は圧縮された確認用。色とアルファの正本は PNG。動画を最終フレームから先頭へ再生し直した時の位置のジャンプは、リニアなテスト移動の開始位置への復帰であり、横反復シームの検証結果とは分ける。
5. 作品自体の反復パターンは当然残る。長距離の背景で反復を目立たせたくない場合は、地形遮蔽・カメラ設計で扱う。今の遠景用途の素材を差し戻すほどの不自然さはない。

**結論:** サイズ・透明・左右接続の未完事項は解消。霧の実寸合成の問題も修正された。この 6 層を「実装用の素材納品」として渡してよいが、「ゲーム内で動作検証済み」とは伝えない。
