# B10 受け光の設定表

4つの既存演出に対する受光の減衰を、エンジンに依存しない JSON にまとめました。**新しい光源を増やす素材ではありません。** 倍率を掛けるのは、条件に合う受け面へ渡す既存の解析光だけです。

## 内容

| 設定 | 倍率 | 適用先 |
|---|---:|---|
| TripleHorn 旧マーカー | 0.12 | 主人公、実際の対象、森 |
| DoubleLash | 0.16 | 主人公、実際の対象、森 |
| HolyMaul 主攻撃 | 0.10 | 主人公、実際の対象、森 |
| HolyMaul 主自己回復 | 0.08 | 主人公だけ |

一般の回復・敵の回復・人形登場時の回復・後続の自動回復には、最後の 0.08 を適用しません。ほかの受け面、プレビュー、条件外は **倍率 1 = 元のまま**です。

### 現行と旧経路

TripleHorn の旧 `TripleHornReceiverFx` と現行の `OwnedAxialContactFx` を分けています。後者は専用の範囲・光量を既に持つため、**旧 0.12 を追加で掛けません**。JSON の `current_route_exclusions` はこの取り違えを防ぐ参照情報です。旧経路を復活させる指示ではありません。

## ファイル

- `Data/hd2d-receive-lights.json`: 4設定、現行経路の除外、色・時間・範囲・適用条件。
- `Data/hd2d-receive-lights.schema.json`: JSON Schema Draft 2020-12。構造検査用。
- `qa/verification.json`: 数値・条件分岐・境界値・公開物の検査結果。
- `qa/reference-samples.json`: 色変換と時間曲線の期待値。実行ファイルではありません。
- `manifest.json` / `SHA256SUMS`: 納品範囲と検算用情報。

## 取り込み

1. JSON と README を読み、実際の描画側で route 全体と受領条件を対応させてください。札名だけで判定しないでください。
2. データの取り込み先は `Data/hd2d-receive-lights.json`。Unity では必要に応じて `Assets/Resources/Data/hd2d-receive-lights.json` へ配置します。**現行版にはこの JSON の自動読み込み口はありません。** この納品では実行コードを変更していません。
3. `operation` が指定する受光倍率だけを既存解析光へ適用します。`reference_light` の色・peak・40.5/63・曲線は元光の説明用です。元光を再生成したり、同じ係数を二重に掛けたりしないでください。`peak` は bridge 処理後・scenario/受光倍率の前の値で、`factory_peak` と `bridge_peak_multiplier` は計算過程です。聖槌回復は factory .10/.045 から target×28/55・floor×.5 を経て、最終peakは約 .05090909/.0225 です。
4. 相手が複数の役割に該当する場合は `recipient_precedence` を使います。たとえば回復の実対象が主人公なら `hero` です。
5. 不明な経路、未提供の条件、無効な入力、対応していない受け面は元の光を保ちます。ゲームのダメージ、回復、ヒット数はこの表から発生させません。

## 色と時間

保存する色は sRGB の16進表記、光量の計算は linear RGB です。sRGB→linear 変換は一度だけ行い、既に線形の入力へ再変換しないでください。

時刻 0 は実際の着弾・回復の受領確定です。Unity の Land は既にこの基準なので、予備動作をもう一度引かないでください。曲線は秒単位で、ドット絵のコマ番号には結び付けません。ドット・滑らかな幾何・シェーダ・画像のいずれの戦闘効果でも使える契約です。

`smoothstep` は u を 0〜1 に収めた `u*u*(3-2*u)`。

- 攻撃の target 光: 45msまで保ち、165msまで滑らかに減衰。
- floor 光: 旧TripleHorn/DoubleLash は時定数 .25秒、HolyMaul は .09秒。現行OwnedAxialは .13秒。
- 俳優が受ける `Hd2dPrototype` の floor 光には別の .90→.14 の変化があるため、target の曲線で代用しません。森にはこの俳優用の係数を掛けません。
- 聖槌回復: 30msで立ち上がり、55〜240msで減衰。受光倍率 .08 自体はこの曲線ではなく、資格を満たす間の定数です。回復の既存 lightGain は FixedSmall なら .65、それ以外は1で、scenario/sourceVisual の値より優先します。
- `geometry_release_reference_seconds` は元形状の参照時間で、光の寿命を上書きする値ではありません。終端・取消し・世代失効・プール再利用は実装側の既存の処理を保ちます。

## 大きさと受け面

H は効果を開始したときの実際の対象俳優の可視身長で、最小 .25 ワールド単位。主人公や森へ光を渡すたびに受け面の身長へ取り替えません。画像の余白、武器の先端、geometry size とも混同しません。

元の4マーカーの target/floor 範囲は **7 / 13 ワールド単位**です。身長比では 7/H・13/H。**7H・13Hではありません。** 聖槌回復の主人公向け近傍半径だけ .30H。現行OwnedAxialは target .70H、floor1.05H、俳優近傍 .24H の別設定です。

`target/floor` は光の置き場、`hero/actual_target/forest` は受け面です。地面位置の光も俳優を照らすので、両者を同じ分類にしないでください。森のシェーダは俳優用の近傍半径を受け取らず、既存の森用減衰を使います。

## 条件と誤適用を防ぐ決まり

JSON の `host_predicate_contracts` を描画側で満たしてから、各 `requires_all_host_predicates` を真にしてください。JSONの文字列は実行するコードではありません。

- 実際のコマンド、前の手札 UID、発生元、効果の実対象、同一世代の登録 event/receipt の参照を合わせます。ここでの実対象は効果の相手であり、光を受ける主人公や森との同一性を要求する意味ではありません。受領は Committed・Exact、拒否理由なし。
- 旧TripleHornは Energy3→1、Growth/Momentum/Weak0、敵Block0・開始HP>15、同じ対象に5ダメージ/HP損失5が3件、DoubleLashは3→2・開始HP>10・同じ5が2件という限定です。別条件へ広げません。
- HolyMaulは登録された単一の主攻撃が基準です。上の固定エナジーや固定ダメージ条件を借用しません。
- 聖槌回復は主攻撃の後の最初の SourceUid=null の回復。0回復でもその枠を使うため、後の自動回復へ所有を移しません。0回復の描画有無は元の実装に従います。
- 受け面ごとに毎回条件を判定し、過去の倍率を保存して使い回しません。新しいヒット、キャラ、戦闘へ持ち越しません。

## Unity 側の差と検証範囲

読み取った版の Unity 契約ライトは範囲7/13固定で、受け面別の解析入力、近傍半径、このJSONの読み込みに未対応です。target/floor の時間曲線も共通なので、元Godotの独立したfloor tailとは異なります。完全再現には取り込み側の接続が必要です。

Godotの解析光の定数40.5/63を、Unityの既存契約光18/28へさらに掛けないでください。また、キャラ全体の `_Receive` を変更する代用は固定キーライトや関係のない光まで変えるので使いません。近似で接続するなら、その範囲を報告してください。

この束で検証したのは JSON の構造・数値・条件分岐です。**Godot/Unityの実戦、GPU、Androidの見え方は未検証。** 数値テストは視覚テストの代わりではありません。接続後は、対象外の相手、ブロック、致死、多段、0回復、取消し、連続使用、戦闘終了を含めて確認してください。
