# 部品（消耗品）の概念設計 — 2026-09-17

死線の「総動員」を作るための、本家ポーションに当たる第3の資源。
**2026-09-17 ユーザー×Claude の ask_user 7ラウンドで骨格を裁定した概念設計。数値・枠・UIは未決（§6）。**
実装はしていない。roadmap の「本家形フェーズ2: ポーション」の後継であり、sts2-improvements [104] を置き換える。

名前は**仮称**（ユーザー裁定「あとで決める」）: 消耗品＝**部品**、通貨＝**巻き**。
本文はこの仮称で書く。「発動」（伏せ札の語）とは衝突させない。

---

## 0. 目的（ユーザーの言葉）

> ローグライクって死ぬ直前に生きるためにリソースを全て総動員して効率考える時間や細い糸を手繰り寄せる感覚が一番面白い。
> そのためには本家のポーションに当たる要素が必要。ただし丸パクリにならない全く異なる仕様で。

作るのは「死線」ではなく「**死線に来た時の解法**」。うちは焚き火25%・幕ボス全回復でHP収支が主戦場なので、
保険を厚くして道中の緊張を消す方向には使わない（§5 のロールバック条件）。

## 1. 理論（なぜ本家のポーションが「細い糸」を作るのか）

1. **糸の正体＝自分が握るレバーの数×組み合わせ**。カードは引き運、レリックは自動。ポーションだけが
   「タイミングを100%プレイヤーが握る・テンポ0・デッキ外」の資源で、死線のパズルに変数を足す。
   回復瓶1本なら足し算だが、エナジー瓶＋ブロック瓶＋火力瓶が手札と噛み合うと「解法を探す時間」になる。
2. **消耗品の制約は2つの蛇口**＝在庫（何個持てるか）とテンポ（1ターンに何個切れるか）。本家は在庫（3枠・2〜3戦に1個）
   だけで絞りテンポは無料＝希少性が制約の代わり。**多く持てる世界では、希少性の代わりに使う瞬間の制約が要る**
   （でないと死線は「全部使う」で終わりパズルが消える）。
3. **死蔵問題（Too good to use）**。解法は3系統＝上限で溢れさせる（本家）／補充する（Estus）／窮地でしか存在しない（格ゲー超必）。
   シレンは「草を抱えて死ぬ」を学習課題として残す。
4. **逆効果**。保険が厚いと道中の緊張が消える（本家の「瓶3本あるからボスは安心」）。

参考にした他作: シレン（草・巻物・杖・壺＝道具の文法）、Estus（焚き火で戻る）、Dicey Dungeons／格ゲー（被弾で溜まる）、
FTL／Darkest Dungeon（長期資産を燃やす）、Into the Breach（手番のやり直し）、本家 Smoke Bomb（逃走）。

### 2.1 骨格を一文で

**倒した敵から「巻き」を貯め、拾った「部品」（固定効果・色中立・一部は回数つき）を自ターンに1個だけ、巻き1で組む。**
本家との違いは4点: ①使うのに通貨が要る（無料でない） ②一部の部品に回数がある（杖） ③1ターン1個 ④効果に「敵の機構への干渉」（打ち消し・召喚を止める・割り込みを止める）がある。

### 2.2 理論との対応

- 在庫の蛇口＝持ち歩き枠（緩め）と回数。テンポの蛇口＝巻き（一律1・上限あり）と「自ターン1個」。
  →「多く持てる」と「総動員がパズルになる」が両立する（§1-2）。
- 巻きは倒すたびに入る（≈1戦闘1）ので、ランを通せば「第2の在庫」に近い。**戦闘内の総動員を絞るのは上限と1ターン1個**。
  死線は「どの順で切るか」の順番のパズルになる（自ターン1個×被ダメ予測が見えている＝計算の糸）。
- 敵ターンに使えないので、部品は**計画の道具**。実値を見てから切る後出しは罠（仕込み札）の専売のまま。
- 死蔵は腕（§1-3 シレン型）。持ち歩き上限は「溢れさせる」ためでなく UI の器の都合だけで決める。

## 3. 部品の台帳（案・数値は仮）

レア度 C/U/R。**基本は1個1回**（本家形）。回数つき＝「杖」は発条・歯車の2種だけ（使い切ると壊れる）。使う＝巻き1・自ターン・1ターン1個。
量は本家の瓶より控えめ（色中立の道具＝札より弱い）。

罠を仕込んでいない戦闘では死に札になる（デッキにリアクションが無いラン・赤では常に腐る）。
候補だった 早巻き・巻き戻し・長発条・予備の枠 は台帳から外す。記録のみ。

## 4. 供給の案（数値は仮）

- 戦闘報酬: 通常戦 40%（外れるたび+10 の pity・当たると戻る＝本家形）、エリート・ボスは確定1。報酬画面に札3枚と並べて「部品を取る／見送る」。
- ショップ: 1枠（C 40G／U 60G／R 90G 程度）。
- ?イベント: 対価・報酬の器に部品を足す（既存イベントの改修は最小）。
- 巻き: 通常戦の勝利で+1、エリート・ボスで+2。上限は仮に **6**（＝ボス前に「貯めるか使うか」が残る量）。開始時 0。
- 持ち歩き: 仮に **5個**（死蔵は腕なので絞らない。UI の匣の引き出しの数）。
- 幕ボス撃破の全回復・焚き火25%は据え置き（裁定「まず足して測る」）。

## 5. 検証と KPI・ロールバック

**検証**: 人間ラン1〜2本（幕1から通し）。Opus ランは機構検証に出さない（コスト規律）。

KPI（レポートの計測ブロックに足す）:
- **死線戦闘の勝率**（HP30%以下で入った戦闘）と、その戦闘での部品使用数
- **部品の使用率**（拾った回数のうち使った回数）と**死蔵**（ラン終了時の未使用回数）
- 部品を使った戦闘の面白さ評価（既存の5段階）
- **リアクションのピック率が下がらないこと**（罠モデルの KPI 据え置き。部品が罠を食っていないか）
- HP収支（幕2〜3の損失・焚き火の休む回数）

ロールバック条件（事前宣言）:
- 部品が死線と無関係に**毎ターンの最適化に溶ける**（使用の8割以上がHP50%超の局面）→ 巻きの上限を絞る／獲得を2戦に1に
- HP収支が緩み**幕2〜3の敗北が消える**（人間2本一致）→ 幕ボスの全回復を部分回復へ（裁定「同時に絞る」を後から適用）
- リアクションのピック率が下がる → 部品が罠を食っている＝守りの部品（発条）の量か供給を絞る
- 部品が全く使われない（死蔵が8割超）→ 学習の問題か供給の問題かを分けてから、構造で押す案（上限・幕で壊れる）を再検討

## 7. 実装の下書き（未着手）

- `data/parts.json`: `PartDef{id, name, rarity, charges, effects: DeclarativeEffect[], target?}`。効果は既存の `resolveEffect` を1回きり実行。
- `RunState.parts: {id, charges}[]`・`RunState.winding: number`（巻き）。獲得は `gainRelic` と同じ一本道 `gainPart`。
- コマンド `UsePart{index, targetIndex?}`（戦闘中・自ターン・`GameState.partUsedThisTurn` で1個）。巻き−1・回数−1・0で捨てる。
- 報酬: `rollRewards` に部品の抽選（pity は ?マスと同じ整数パーセントポイント）。ショップに1枠。
- 干渉は `intent` の打ち消し（既存 negate）・召喚/分裂の抑止・`firedInterrupts` に印。
- 逃走（煙玉）は run 層（戦闘を離脱・報酬なし・HP維持。幕ボスでは使用不可＝UI は理由つきで灰色）。致死耐えは `deathSave` の戦闘限定版。
- ゴールデン: 部品を拾わない限り RNG 消費は不変にできない（報酬の抽選が1回増える）→ 再生成が要る。C# 追随は TS で人間ランを測ってから。
