# 伏せの再定義：罠モデル（2026-09-13 議論・裁定）

ユーザー提起「リアクションが攻撃の上位互換になっている（リスクが低くリターンが勝つ）／通常攻撃よりもっさりして爽快でない」を起点に、
ask_user 4ラウンドで「伏せの面白さは何か」から整理し直した記録。**裁定済み・未実装**。

## 0. 結論

- 伏せの面白さは**読み合いではない**。本体は **①罠の的中**（見えている敵の行動に答えを仕込み、敵が踏む瞬間が山場）と **②敵ターンの能動性**（敵ターンにプレイヤーの出来事が起きる）。
- 上位互換の正体は、条件が最も緩い基本リアクション（攻撃された時＝ほぼ毎ターン成立）に「伏せ枠の占有」を理由に2倍前後のレートを付けていたこと。占有は無期限保持＋回収で実質コストゼロだった。
- 処方＝**罠モデル**: 伏せたターンは鳴らない（準備）→ 翌ターン・翌々ターンの敵フェーズだけ生きる（2窓）→ 外れたら捨て札。回収は廃止。数字は据え置き、発火に「形」を足す。
- 副産物として**読みが本物として復活する**: 仕込む時点で見えている意図は今ターンの分だけで、罠が生きるのは次ターン以降。ローテーションの学習（探り屋の三度目・砥石の三拍子・大亀の防御→防御→大薙ぎ）が仕込みの根拠になる。意図を隠さずに読みが立つ。

## 2. 面白さの分解と裁定

| 候補 | 要るもの | 現状 | 裁定 |
|---|---|---|---|
| 読み合い（敵の手を当てる） | 隠れた意図 | 意図公開が核なので成立しない。実測でも面白さに差なし | **面白さの源ではない** |
| 後出しの情報優位（実値を見て決める） | 温存する理由 | 発動率71%。決断が潰れている | 主役ではない。確認窓は残す（温存が1回だけできる寿命と整合） |
| **罠の的中** | 見えている行動への答え | 先制の蔦槍・共鳴する茨・弾け実が Opus ランの山場 | **本体** |
| **敵ターンの能動性** | 敵ターンの出来事が派手 | 「返し10」の数字だけだと遅い打撃に見える | **本体**。形で派手にする |
| ブラフ・挑発（setAlt） | 敵の反応 | ユーザー「分岐の読みが煩わしい」 | 主役ではない。準備ターンへの罰として残す |
| 攻防一体の資源効率 | — | 上位互換問題そのもの | 面白さではなくレートの話 |

ユーザー裁定（ask_user）: もっさりの正体＝「効果が1ターン遅れる」＋「分岐の読み」／リスク＝「札そのものと通常札との明確な差別化」／
必要性＝「読み合いじゃないのでは。まず整理」／上位互換と感じた札＝茨の返し・守りの蔓・先制の蔦槍・打ち消し／
遅れの解＝「伏せたターンは発火しないくらい遅らせて、その分リターンを大きく」。

## 3. 罠モデルの規則（裁定済み）

| 規則 | 内容 | 裁定 |
|---|---|---|
| 準備ターン | 伏せたターンの敵フェーズでは**鳴らない**（自己誘発も含め一切）。敵はこのターンの札を「新鮮」と見て反応する（見切り・破壊） | ユーザー案 |
| 寿命 | **翌ターンと翌々ターンの敵フェーズ（2窓）**。温存は1回だけできる | 推奨採択 |
| 期限切れ | 2窓目の敵フェーズ終了時に鳴っていなければ**捨て札**へ（消滅持ちは消滅） | 推奨採択 |
| 回収 | **廃止**（RetrieveSetCard・同ターン0E伏せ直し）。罠は仕込んだら押し戻せない | 「ターン経過で消える」案の帰結として |
| 確認窓 | **今のまま毎回確認**（発動/温存） | ユーザー裁定 |
| 汎用リアクション（返し・ブロックのみ） | **罠として残し**、発火を大きく | ユーザー裁定 |
| 大きくする物差し | **数字でなく形**。数値は据え置き（pre窓軽減150%上限も据え置き）、発火に副次効果を1つ | ユーザー裁定。配分は札ごと（§5） |

### 3.1 なぜこれで上位互換が消えるか

- 伏せた札は少なくとも1ターン仕事をしない（打撃なら今殴れる分が無い）＝**テンポの対価が実在する**。
- 2窓で鳴らなければ捨て札＝**外れが実在する**（防御ローテの敵・タメ系・逃走・分裂で空振りする）。
- 回収が無いので**やり直しが利かない**＝仕込む前に読む。
- レートは据え置き。差別化は「踏んだ敵への罰」「次ターンへの繋ぎ」という**通常札には無い形**で作る。

### 3.2 なぜもっさりが消えるか（消えないか）

- 遅れ自体は消えない。**遅れを「予約」から「仕込み」に読み替える**のがこのモデル。仕込んだ瞬間に敵が反応し（罰型の分岐・壊しに来る）、翌ターンに踏むかどうかが賭けになるので、待ち時間が緊張になる。
- 確認窓は据え置きなので敵ターンの手数は減らない。寿命2窓により「温存」が本物の選択（次窓に賭けるか）になるので、クリックの税から決断に戻る想定。効かなければ次の処方＝「候補1枚で温存の理由が無い時は自動発動」（今回は見送り）。

## 6. 実装の当たり（未着手）

- engine: `CardInstance.setTurn`（伏せた `state.turn`）。窓の判定＝`state.turn - setTurn ∈ {1,2}` の敵フェーズだけ候補に載せる（set-base の候補抽出1箇所）。`finishEnemyPhase` で `state.turn - setTurn >= 2` の残存札を捨て札（消滅持ちは消滅）へ＝イベント `SetCardExpired`。`RetrieveSetCard` は拒否（旧セーブ互換のため型は残す）。`wasSet` 撤去。`setFresh` は不変。

- データ: 緑5枚の形（§5）。回収の紐の作り直し。
- テスト: 準備ターンに鳴らない／2窓目の終わりに捨て札／消滅持ちは消滅／回収拒否／見切りは準備ターン／自己誘発は準備ターンに鳴らない／かすみ2枠の重ね／条件付き罠の規約テスト（大潮の否認の実測を根拠にした注記）の書き換え。ゴールデン8本は再生成。C# 追随。

### 9.2 接続表の漏れ（C。§4 に追加）

- 準備ターンの敵フェーズ終端で `ReactionWhiffed`／`ReactionUnaffordable` を出さない（統計の嘘）。
- 期限切れ消滅は `fireExhaustTriggers`→`fireNecroEffects`（衝動失効と同じ順）。**期限切れ由来で敵が死にうるので `checkCombatEnd`＋早期 return が必須**（finishEnemyPhase には現在 checkCombatEnd が無い）。
- 旧セーブに `setTurn` が無い → `setTurn ?? state.turn` のフォールバック（無いと NaN で永久死に枠）。
- 回収を使った既存ラン（人間・Opus）のリプレイは回収の手で打ち切り。ゴールデンは回収0件で無傷、SetCard は8本中7本（red-9101 だけ不変の可能性）。
- **致死時の post 窓**: 救命札（死中の活・冥府の手・呪詛返し・怨嗟）を「死にそうなターンに伏せる」ことが不可能になる＝黒の「土壇場の一手」は実質消える。凍結色なので記録のみ（裁定待ち）。
- 手数の鏡（mirrorHits）は準備ターンが「1枚数えて何も起きない」純損。因縁の無形ターンは返しが1ダメ。アーティファクト4体（苔の主・斧鬼・巨面・箱兵）は急所・威圧の形を弾く。円蓋は「2ターン先を見えないまま賭ける」。
- `setBranchFlipRisks` は `setCards.length !== 1` で警告を出さない → 2枠で「準備中＋生きた罠」が常態化すると警告が消える。条件式を「他に新鮮な札が無いか」へ。
- `analysis.ts` の TurnMetrics に `SetCardExpired` を足さないと §7 の指標が機械で読めない。
- destroy-set（combat.ts:2071）は消滅を無視して捨て札へ送る既存の非対称。期限切れは真似ない。
- hold-manual は準備ターンの対価を払わないので副次効果だけ乗る（記録用方式なので実害なし）。
- 影響範囲: 伏せ機構に触れる it 91（25ファイル）、うち「伏せた同ターンに鳴る」前提が61（20ファイル。`toNextTurn` ヘルパで機械的に前進可）。回収廃止＝engine 1関数・型4・UI/CLI 4・Unity 2・テスト6ファイル・レリック1。wasSet の参照は4箇所で撤去は安全。C# 追随4ファイル。

### 9.4 その他の要監視（A・C）

- 固定ローテの大技敵（大亀・砥石・巨面・斧鬼・門番）では「hone が見えたら仕込む」の参照表になる。weighted 敵で本物の賭け。両者の面白さを別集計。
- 罠壊し（鮮度無視・setCards 全破壊）は回収の逃げ道が消えて一方的に強化。破壊 weight 2→1 か「破壊も手札へ」の候補。まず実測。
- 準備ターン＝3T戦闘の敵フェーズの1/3が無応答＝HP収支の悪化。最初の2ランで幕別 HP 損失を旧値と比較。

- 2枠（かすみ・二重の符）×見切り窓側化で「常に張り詰めた罠がある」蓋が作れるか（1E＋札を3ターンごとに払う＝無料ではない）。監視。

### 9.5 総評（B: 見込み 3.5／5。9.1 の #2・#4・#3 を入れれば 4.0、入れなければ 2.5〜3.0）

罠モデルは「上位互換を消す」には届き、「罠の的中を山場にする」には半分届く＝予告型の敵・エリート・ボスで今より良く、毎ターン殴る通常敵で今より悪い二峰化。二峰化は幕3が最も面白い傾向（人間#8・#9）と同方向で受容できるが、見切りの反転と自動発動と反応型の形が無いと、失う体験が得る体験を上回る。
