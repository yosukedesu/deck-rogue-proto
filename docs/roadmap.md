## Phase A: 面白さ検証スプリント 【最優先・1〜2週】

simで測れない唯一のものを測る。**このゲートを通らない限り、下流に1円も投資しない。**

- [ ] プレイテスト計画: リーダー4人×各3ラン以上を実機（スマホ/PC）でプレイ
  - 記録項目: 「もう1ラン」欲求の有無／悩んだ瞬間・作業だった瞬間／伏せ（発動/温存）が楽しい敵・退屈な敵／死因の納得感
  - 特に見る: 道化戦のブラフ駆け引き／妖術師の負傷がストレスか戦略か／威嚇の体感／門番のタイマー圧
- [ ] 摩擦の修正: テストで見つかったUX障害のみ直す（新機能は足さない）
- [ ] 敵の顔付け: 1行フレーバー追加（安価・プレイ感に効く）
- **ゲートA: 「続けたくなるか」の自己判定。** Yes→Phase B/C並行へ。No→コアループの設計相談に戻る（世界観と同じく複数案出し直し）

## Phase B: ルール完成 【2〜4週・Aと並行可】

Unity移植の凍結チェックを消化する。すべてTS側で実施（sim検証力があるため）。

- [ ] チャオス構造修理: 衝動エンジン化の設計相談→実装→sim（ループ安全設計込み）
- [ ] レリック実装: フックの口は開いている。ラン報酬・焚き火・エリートの報酬先として設計
- [ ] 負傷への回答: 浄化・消滅系カードをプールに追加（対策カード原則）
- [ ] スコープ決定: マップ分岐／エリート（挑戦オファー型=opt-inでストレス回避）／イベント——入れるか切るか
- [ ] バランス最終調整: 全リーダー8〜15%帯・0%マッチアップの再点検
- **ゲートB: ルール凍結宣言**（以後の変更はC#追随コストを払う）

## Phase C: 製品スコープ確定 【1週・要決定事項が中心】

- [ ] **ビジネスモデル決定**（最重要決定。全設計に波及）
