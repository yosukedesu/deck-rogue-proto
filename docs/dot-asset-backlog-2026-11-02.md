# dot に回し続けてもらう素材の不足一覧（2026-11-02・最高品質へ）

ユーザー「最高品質のクオリティにするため dot に画像素材や 3D オブジェクト素材で不足しているものやエフェクトなどをリストアップしてほしい。dot は常に素材作成として回しっぱなしにする」。
Unity の `Assets/Resources/Art` と `Audio`・`Stage` を棚卸しして、**無いもの・仮のもの・質が足りないもの**を並べた。優先は品質スプリント（`docs/design/quality-sprint-2026-10-28.md` §2）の順＝幕1 の一周を完成品の質にする → 戦闘の残り → 幕2/3。
dot への依頼文は `docs/codex-dot-request-2026-10-12.md` §22。dot が納めたら、この表の「状態」を更新する。

## 0. 納品の形（全部に共通）

- **PNG＋JSON**（エンジンに依らない形。CLAUDE.md「dot への素材の依頼は PNG＋JSON」）。raw の原本・実寸 PNG・README（出所・規格・使い方）の 3 点＝ひばなの核と同じ形。
- 画風は `docs/art-bible.md`。**絵はドット、紙と文字はなめらか**。敵・キャラ＝2.5〜3 頭身・斜め 3/4・オクトラ風・豆の目・口なし・**人型は描かない・地面や背景を描かない**。小物は `view: side`・等間隔の粒は禁止。
- 粒: 戦闘のキャラは 1 ドット＝3px（dot の敵の組と同じ。スマホ 1.8）。リーダーは **みぞれ・ひばなの規格 128×84・足元 y76・x60** に揃える（このはの 88×64 は旧規格・差し替え可）。
- 色の生の値は C# に書けないので、色の表は JSON（例 `Data/hd2d-palette-defaults.json`）。
- 法線 `_n.png` は `scripts/sprite-normals.py normals` で作れるので任意。
- 置き場と取り込みの道具は各項目に書いた。名前は id そのまま（`leader_izzet`・`enemy_probe`・`relic_abacus`）。

## 0-2. 止まらないための規約（2026-11-02 ユーザー「方向性だけ確認して、あとは回しっぱなしに。確認で止まるのは効率が悪い」）

- **dot は質問で止まらない**。規格に書いてない事は dot が決めて README に「決めた事」として書く。こちらは受け取ってから直すか、作り直しを表に積む。
- **採点を待たない**。dot は束を納めたら次の束へ進む。採点（4 未満）の作り直しは、表に「A1-r」のように別の行で積み、dot は今の束の後に拾う。
- **束の単位**＝表の 1 行（A1 のような大きい行は人ごと・幕ごとに割ってよい）。1 束＝1 枝 `codex/assets-<行>-<日付>`＋README＋`manifest.json`（id・ファイル・実寸・足元・コマ数・取り込み先）。
- **順番は表のとおり**。別の行を先にやる理由（素材の都合など）があれば README に 1 行書いて進めてよい。
- **触らないもの**: 立ち絵・BGM・キービジュアル・`src/engine`・`src/data`・Unity のコード。素材と JSON だけ。
- **こちら（Claude）**は納品が来るたびに取り込んで撮り、ユーザーには束ごとに 1 枚の並べたシートで採点を頼む（ユーザーの空いた時に。dot の進行は待たせない）。

## 3. こちら（Claude）側の受け入れ手順

1. 納品の枝を fetch → README と JSON を読む → 規格（大きさ・足元・コマ数）を `python3 -I` で検算。
2. 置き場へ写す（敵は `scripts/import-enemy-dotset.py`／`import-enemy-moves.py`、札は `Art/cards` → `scripts/sync-web-art.sh`、422 の絵は `ArtImporter`、法線は `sprite-normals.py normals`）。
3. `scripts/unity-win.sh compile` → `shots state` で該当の場面を撮る → ユーザー採点（4 未満は作り直し）。
4. この表の状態を更新し、`docs/art-todo.md` と `docs/pixellab-assets.md` の該当行に「dot 版へ置き換え」と書く。
