# R3 UI の作り直し 仕様（2026-10-02・審査で決めた形）

三周目「R3 UI の作り直し」の実装の一次資料。2つの設計案（案A「足元の帳面」・案B「左下の匣と右下の帳」。模型と計算は scratchpad の `r3ui/caseA`・`r3ui/caseB`）を読み比べ、**PC は案B の骨組み、スマホは案A の骨組み**に、両案の良い所を足して1つにした。
元: 分析 `docs/design/hd2d-r3-analysis-2026-10-01.md` §6・§7／計画 `docs/design/hd2d-round3-plan-2026-10-01.md` §0 の裁定1／試し撮り `uitrial=1`（`R3A_` の印）／ユーザー裁定 2026-10-02「本番に入れる」。

座標の約束: PC はキャンバス＝画面 1920×1080 で、**「行」は上から**・「y」は下から（y＝1080−行）。スマホは**キャンバス 1462.75×675 の上から**（撮影 1920×886 の px はキャンバス×1.3126、S25 実機は×1.6）。

---

## 0. 結論

**主人公の頭の上〜足元のまわりと、足元の下の草の帯（PC 行 800〜950・x 512〜1460）には、普段は UI を1つも置かない。** 置き場は次の4つだけ。

| 置き場 | PC | スマホ |
|---|---|---|
| 足元の帳（自分の HP と受けるダメージの見込み） | 主人公の足元の 10 下・x 204〜500 | 主人公の足元の 8 下・x 24〜384（からくりも入れる） |
| からくり・ギア・置物 | **左下の匣**＝エナジーの輪の真上に下から積む柱（x 32〜184） | からくり＝足元の帳／ギア・置物・状態＝**今の上の帯** |
| 敵の帳 | 各敵の足元の 10 下・60（予告ありは全員 88） | 各敵の足元の 8 下・53（予告ありは 79） |
| 四隅 | 上部バー・輪と灯籠・山札/捨て札/消滅・ターン終了（今のまま） | 同じ（輪・灯籠・山札は下へ寄せる） |

手札は沈めて、上の帯（コスト玉・名前・挿絵の上）と**要の数字の札**だけを見せる。触れた札だけ上がって本文が読める。

### 選んだ理由（判定の軸）
- **① 本家と並べた時**: 案A の PC は「段2 持ち物の帯」（ギア・置物、x 342〜1130・行 820〜874）が草の帯のまん中を横切る。本家が草の影絵を見せている所なので、ここに UI を置かない案B を採った。案B の匣は画面の左端の、いちばん暗い木の幹の上にある。
- **② 判断に要る数字**: 両案とも敵の帳に予告の行を戻した（2026-09-16 の教訓）。予告の行の高さは案A の「1体でも予告があれば全員 88」にした（今の `uniformForecast`。帳の下端がそろい、目で追いやすい）。状態の札（成長・勢い・弱体…）は、案A と同じく足元の帳の4行目に置く。案B の「匣のいちばん上」だと、主人公の頭の高さまで柱が伸びて読みにくい。
- **③ スマホ**: 案B のスマホは変える物が多すぎた（灯籠の移動・札 0.85 倍・ターン終了の移動・選択式の窓）。それに確認の窓が主人公を覆う。案A は今の上の帯（指の的 68×66 の名前つきギア）を残し、変えるのはからくりの置き場と縦の割り付けだけ。ただし「押した間に札の全体が親指より上に出る」持ち上げ量（+130）は案B から採った。
- **④ 今の操作からの変化**: 人形の足元の札は今の作法（各人形の真下・`ArrangeDollTags`）のまま。案B の「棚」は、前列と後列の人形の x が重なる所で、どの札がどの人形の札か分からなくなるので採らない。スマホの操作（タップですぐ撃つ・長押しで拡大・狙う札は矢）も変えない。
- **⑤ 手間と危険**: 手札の沈めは案A の 168・扇の下がり 4 にした。10枚の時でも端の札の要の数字が画面に残る。要の数字の札の位置は案B の「左上（コスト玉のすぐ下）」にした。手札は右の札ほど手前に描く（`SyncHand` の `SetSiblingIndex(i)`）ので、重なった扇でも札の左上は隠れない。案A の「上の真ん中」は、10枚で隣の札に隠れる。

### UI の面積の見込み（両案の物差し）
PC 13〜15%（二周目 21〜26%・本家に近い）。スマホ 27〜34%（二周目 42〜46%。指の的 48 と 1.6倍の字が下限を決めるので、15% には届かない）。

## 1. 旗（全員共通の取り決め）

| 旗 | 中身 |
|---|---|
| `uilayout=r3` | **箱庭の既定**。この仕様の割り付け（PC とスマホの両方） |
| `uilayout=r2` | 二周目の割り付け（足元の線 PC 0.407・スマホ 0.525／手札の沈め PC 19・スマホ 17／`PcSelfStrip`・`PhoneSelfColumn`・帳面は自分の札の上端にそろえる・扇の下がり 10・「場に出す」線は画面の 36%・今の `ReactionWindowRect`・今の `GearUi` の置き場・**手札の後ろの暗幕は全幅（`deskshade` を書かない時の既定が full）**） |
| `uitrial=1` | `uilayout=r3` の別名（今の撮影の一覧がそのまま動く）。`uitrial=0` は何もしない |
| `deskshade=full\|hand` | 書いた時はその値。**書かない時は割り付けで決まる: r3 → hand・r2 → full**（`HD2DFlags.DeskShade` の getter。r2 は暗幕も二周目と画素一致。2026-10-02 読み合わせ） |
| `groundline=` | 書けば r3/r2 より優先（今のまま） |

コード:
- `HD2DFlags`: `public enum HD2DUiLayout { R3, R2 }`・`UiLayout`（既定と Reset は R3）・`uilayout=` を読む・`uitrial=1` は `UiLayout = R3` に読み替える（`UiTrial` の getter は `UiLayout == R3` を返す）・ダンプの `flags` に `uilayout` を足す（`uitrial` も残す）。
- `BattleScreen.R3 => Hd2dLayout && HD2DFlags.UiLayout == HD2DUiLayout.R3`（**PC とスマホ共通**）。今の `R3A_UiTrial`（`!UiKit.Phone` つき）は `R3 && !UiKit.Phone` に置き換え、スマホの枝は `R3 && UiKit.Phone` で書く。r3 の分岐は全部この1つの値を読む。
- `StageCamera.GroundLineRatio`: `DioramaCamera` のとき `Phone ? (R3 ? 0.45 : 0.525) : (R3 ? 0.36 : 0.407)`。
- `stage=old` は `Hd2dLayout` が偽なので、r3 にならず1画素も変わらない。

- 沈め 168 にする理由: 試し撮りの 183 だと、10枚の時に端の札の要の数字の札が画面の外に出る。168 で扇の下がりを 4 にすると、要の数字の札の下端は画面の下から PC 37px 以上、スマホ 39px 以上（撮影の px）になる。layout-check の門 36 を守る。
- **要の数字の札（新しい部品）**: `CardView` が `InHand && BattleScreen.R3` の時だけ作る（名前 `keynum`）。拡大の窓・報酬・店・r2 には出さない。
  - 置き場: 札の単位で x 12〜（数字の幅）・y 50〜74（上から。コスト玉は y −6〜46 なのでそのすぐ下）＝挿絵の窓の左上。手札は右の札ほど手前に描くので、札の左上は扇が重なっても隠れない。
  - 中身: 本文の最初の量の効果を1つ（**条件つきの効果＝condition 付きは数えない**。「上限5以上でさらに6」「急所なら4」・猛り火など。盤面での成否を手札の札の組み立てで判定できないので足さず、触れて本文で読む。ダメージは onPlay の条件なしの dealDamage だけを集める＝`CardView.KeyNumDamage`）。値は**手札の本文と同じ実値**（`CardText` の手札の式＝成長・勢い・弱体・狙った敵の急所と装甲込み）。形は「剣の絵＋6」「剣の絵＋4×2」「盾の絵＋5」「心の絵＋6」「2ドロー」「+1E」。選択式・量の無い札・状態異常の札は出さない（触れて読む）。
  - 見た目: 紙（濃）`PaperFx.Tag2`＋墨の縁・数字 Deco 17（手札 0.92 倍で 15.6px）。新しい色は使わない。
  - 触れて上がっている間は隠す（本文に同じ数字がある）。
- スマホの操作は変えない: タップですぐ撃つ／押した瞬間に札が上がって全文が出る（今の PointerEnter）／下へずらして離すとやめる／長押し 0.5秒で拡大／敵を狙う札はドラッグで矢（矢は沈めた札の上端から）。
- 7枚以上で名前を左寄せにする作法（`CompactName`）は今のまま。

`BattleScreen.R3PcWindowRect(g, st, W0, H, actingEnemy)` を1つ作り、`ReactionWindowRect` の r3 の枝と `GearUi.BuildWindow`・`BuildMore` がこれを使う（r2 は今の式）。**置き場の幅は H で変わる（高い窓は主人公を避けて狭まる）ので、呼ぶ側は「幅で中身を測る → その H で置き場を取り直す」を幅がそろうまで回す（2回まで）。中身（説明の行数・ボタン・ギアの並び）は最後の幅で組む。**
