# 段0: 分析（ここが本題。手を抜かない）
1. **目で見る**。本家 ot16（と OT1/OT2 の夜・森・洞窟の戦闘）と二周目の撮影を同じ大きさで並べ、1:1 の切り抜き（主人公・敵・足元・霧の帯・上の4割・左右の端・手前）を作って Read で見る。数字より先に「何が違って見えるか」を言葉にする。良く見える所も挙げる。
2. **層に分解する**。本家の画を、空と樹冠・奥の木・霧の帯・中景・座席の地面・キャラ・手前・光（月光の筋・灯・粒）・ポスト処理（ぼかし・ブルーム・減光・色）に分ける。それぞれ「何で作られているか（板・立体・粒・ポスト処理）」「画面のどこを占めるか」「明るさと色」「細かさ（ドットの密度・模様の量）」を推定する。同じ表を二周目にも作り、差の大きい順に並べる。
3. **根本原因を探す**。症状（霧の中の幹が灰色の柱の列に見える・霧の帯が太い・左が黒い壁・地面の縁・光の粒が見えない・敵が小さい など）の一つ一つについて、原因が「値」か「作り方（仕組み）」か「絵（素材）」か「カメラと UI の割り付け」かを切り分ける。前提も疑う。例えば、今のカメラ・霧のモデル・板の作り方のままで本家に届くのか。数字の門は通っているのに見劣りするのはなぜか（物差しが目的からずれていないか）。
4. **HD-2D の作り方を調べる**。記事の写しと Web（Team Asano・Acquire の講演、UE4 での HD-2D の解説、ファンの分析）から、本家が使っている技法を集める（立体に貼ったドットのテクスチャの密度・ビルボードのキャラ・被写界深度・ブルーム・光の筋・点光源・霧・粒・減光・色調）。うちの実装（Unity 6・URP 17 Forward+）で何が同じで何が足りないかの表にする。URP で使える物（Volume・ブルーム・SSAO・Decal・点光源の影・ボリューメトリックの代わり など）も含める。
5. **改善案を出す**。各案に「見た目への効き 1〜5・手間・危険・今すぐできるか（コード・データ・既存の絵）／10/7 以降か（PixelLab の新しい絵）・確かめ方」を付け、効きの大きい順に並べる。小手先の値の調整だけでなく、作り直しも候補に入れてよい（例: 木を立体にする・奥を何層もの板にする・ライティングの仕組みを変える・カメラと UI の割り付けを変える）。案ごとに、Python で画像の上に作った予想図（模型）を付けられるなら付ける。
6. **10/7 の PixelLab の発注書の下書き**。裁定済みの「1体で出る幕ボスを 160 の枠」「1〜2体で出る幕1の敵を 80 の枠」と、舞台の絵（霧に溶ける針葉樹の列・枝つきの幹・苔岩・立った草の株・土手のタイル など）の注文文を書く。docs/pixellab-assets.md と CLAUDE.md の PixelLab の勘所に沿うこと（透明背景は面積3万pxまで・等間隔の粒は不可・小物は view: side の正面の立面図・敵は low top-down でプレイヤーと向かい合う斜め左手前）。

# 過去の失敗（繰り返さない）
- 数字の門を全部通しても、本家と並べると見劣りした（二周目 3〜3.3）。物差しが本家の見え方を測っているかを疑うこと。
- 高さの霧（低い所ほど濃い）は、低いカメラだといちばん明るい所が頭の後ろに来る。そのため距離の霧に変えた（二周目の計画 §0）。
- 木を「霧に沈めた暗い板」にすると、同じ太さの灰色の柱が並んで見える。本家の霧の中の幹は細く（画面で 8〜30px）、間隔は不規則で、上に枝と葉が広がる。
- 暗い木立と横の減光を重ねると、模様のない黒い壁になる。
- 霧の面の縁は、真っ直ぐな横線として見える。
- 低い見下ろし（5°）では、地面の縁のタイルが縦に潰れて四角い欠片の帯に見える。
- 直しの輪で値を動かすと、別の所が壊れる（霧の面 mist-lip の横線は直しの輪1で入った）。直したら必ず目で見る。
- 1つずつ撮影して確かめると何時間もかかる。ファイル別のレーンで並列に書き、撮影は最後にまとめて1回。
