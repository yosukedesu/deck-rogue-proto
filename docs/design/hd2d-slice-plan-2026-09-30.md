# HD-2D 見本（幕1の1戦闘）確定計画

2026-09-30。この計画は、調査・4案・審査の結果（`scratchpad/hd2d-result.json`）、提案書（`docs/design/hd2d-quality-proposal-2026-09-30.md`）、2つの審査（実装の審査と画質の審査）をもとに書いた。

## 0. 前提

### ユーザーの裁定（2026-09-30。CLAUDE.md「HD-2D 刷新の裁定」）
1. 外注はしない。絵は PixelLab（月の生成枠がある）と手直しとコード生成で作る。
2. 舞台は全部3Dの箱庭に作り直す（A案）。キャラは世界の座席に立ち、UI がキャラの位置を追う。
3. 舞台の上に常に出る札（敵の帳面・自分の札・上部バー・頭上の意図の札）は夜色の札にする。紙のまま残すのは手札・確認の窓・メニューだけ。
4. 主人公の大きさは、62ドットと48ドットを並べた見本を見て選ぶ。

### 反証で直した事実（hd2d-result.json の verify）のうち、この計画が前提にするもの
- 本家は人工の大物（建物・櫓）を3Dで作り、木や岩などの自然物は基本が2.5D（表側だけ立体の絵）。
- ぼかしは、座席にいるキャラが読めることを優先する。弱いぼかしも選べるようにしておく。
- 画面のギザギザ取り（AA）はキャラの板に掛けない。
- Linear 色空間への切り替えは、2段階で元に戻せるようにする（受光を0にする／設定を丸ごと戻す）。
- スマホの30fps は、今も Unity の既定で出ている。S25 の性能は、計測用の APK を用意しておき、実機がつながった時に測る。

### 作業の制約
- 実装は Claude の並列の作業者（レーン）が行う。Unity の作業コピーは1つしかないので、レーンは Unity でコンパイルできない。代わりに W0 で用意する dotnet の型検査を使う。compile・build・撮影は、各波の終わりに統合担当が1回ずつまとめて行う。
- 撮影には `scripts/unity-win.sh shots state` を使う（Autopilot.StateJump のキー）。合否を決める比較の撮影は、1行ごとにゲームを起動し直して撮る。
- ゲームのルール（src/engine と C# のエンジン）は触らない。
- 作業は枝 `hd2d/slice` で行う。main は遊べる状態のまま保つ。
- スマホの実機は今つながっていない。スマホの見え方は、PC で `SHOT_W=1920 SHOT_H=886 UISCALE=1.6` と `tier=phone` を付けて再現する。

## 1. 目標

### 1-1. 見本の完成形
幕1・坑口の森の戦闘を1場面だけ、完成品の質で作り、本家と並べて判断する。撮るのは PC（1920×1080）とスマホ相当（1920×886・UI 1.6倍・`tier=phone`）の2通り。

**撮る場面**
- (A) このは＋牙嵐の狼（`enemy=enemy_wolf`）
- (B) 同じ舞台で脳筋オーガ（`enemy=enemy_brute;boss=1`）
- 壊していないかの確認用に、(C) 狼と妖術師と太鼓（3体）、(D) 噛みつく巻物・四巻（4体）、(E) ひなた＋人形9体

**画面の上から下まで**
- **上の約1/3**: 奥へ3段のひな壇がある。岩の崖と苔の天面、大樹の幹が暗い影として3〜4層に重なる。その奥で、坑口の脈の青緑の光を受けた霧が明るく光る（今はこの帯がほぼ黒）。尾根に3Dの坑口の櫓が立ち、滑車が回る。月光は左上の手前から差し、樹冠の隙間から光の筋が落ちる。月の向きは最終的に、絵に描き込まれた光の向きを測って決める（art-lint）。
- **中ほど（座席の帯）**: 平らな空き地。「舞台の灯」（全員に同じ向き・同じ色で当たる固定の光。色は中立からわずかに寒色）と、大きく不定形な木漏れ日が地面とキャラに乗る。キャラの影は舞台の灯から1方向だけ、右奥へ落ちる。地面は模様の弱い静かな面にし、光溜まりと影が先に目に入るようにする。
- **手前**: 座席より一段低い段に羊歯・根・岩を置き、左右の中段の縁と手札の上の下隅に、枝葉が大きくぼけた額縁を置く。UI の札に隠れる所には置かない。手札はその上に少し沈めて置く。

**そのほかの形**
- **ドットの粒**: 座席の位置で、キャラも地面も岩も1ドット＝4px にそろえる。世界は25ドット/unit にそろえる。遠くはちらつかず、近くはドットの角が立つようにする。
- **画面の紙**: 舞台の上に常に出る札は、夜色の地に紙色の文字にする（裁定③）。足元の線の目標は画面の上から62〜68%（今は57%）。最終の値は、帳面・自分の札・手札が脚と足元を隠さない、いちばん低い線にする（§2-3・P20）。
- **主人公**: 62ドットと48ドットを並べる。まず v2 を縮めた安い見本で「大きさだけ」を W2 の途中で選んでもらう。48が選ばれた時だけ清書を作る（P23）。背丈の比はオーガに対して約1.6倍／約2.1倍、狼に対しては48ドットのほうが小さくなる（狼の体は53ドット）。

## 2. 設計

### 2-1. 全体の形（3つの層）
- **舞台**: 世界の中の3Dの箱庭（新しい Diorama）。
- **キャラ**: 世界の座席に立ち、光を受ける板（StageUnit の作り替え）。
- **画面の紙**: ScreenSpaceOverlay の UI。今のまま、光とぼけは受けない（「光と空気は舞台だけ」の規約）。

UI の置き場は、世界の座席をレイアウト用のカメラ（揺れと寄りを含まない `_camBase` と、その回転）で写して決める。今の `Stage.ProjectFeet` と同じ計算で、UI が世界を追う形になる。

見本は幕1だけ。幕2・3と今の舞台は `stage=old` で残す（比べる元と、戻り先のため）。

### 2-2. 舞台の組み方
**作り分け（本家どおり）**
- 人工の大物（坑口の櫓・柵・標）は完全な3D。
- 地形（地面・崖・段・岩棚・大岩）は3Dのメッシュ。
- 樹冠の葉・茂み・羊歯・大岩の一部などの自然物は半立体。スプライトの輪郭から高さを作り、表側だけ膨らませて裏面を持たないメッシュにする（`ReliefMesh`）。カメラの方へは回さず、決まった向きで立てる。深さは幅の0.12倍から試す。
- 草・小石・花だけは2Dの札にする。
- 裁定②の「全部3D」は、「カメラの方を向く書き割りの板を舞台から無くす」と読む。
- 大樹の幹は「3Dの筒」（`trunk=mesh`）と「既存の `act1_tree_giant`／`oak` から作る半立体」（`trunk=relief`）の2通りを撮る。W2 の途中の比較シートで、この読み方をユーザーに確かめる（§5 W2）。

**形の作り方**
形はコード（C#）で作る。Blender は入れない。`DioramaMesh` が、面の平らな押し出し（崖の帯・段の角・柵）、低ポリの面取り多面体（岩。8〜20面で、面ごとに平面の UV）、円筒に展開した UV を持つ幹と根、櫓を作る。
- 崖と段の凹凸は輪郭（平面の中の折れ線の位置）にだけ入れる。法線方向のノイズは入れない。折れ線は0.32〜1.28 unit の格子に合わせる。
- 陰は頂点色で付ける（凹みほど暗い AO）。
- 後で `Resources/Stage/Act1/Models/<名前>` に FBX を置けば、同じ名前の形と差し替わる。

**置き場と組み立て**
置き場は `Resources/Stage/act1_layout.json` に書く（部品の種類・道の座標 t と s・高さ・向き・大きさ・種・材質の回し方）。`Diorama.Build` が実行時に組み、静的な部品は `StaticBatchingUtility.Combine` でまとめる。ただし、回る滑車・カメラに合わせて置き直す額縁・揺らす霧や光の筋は、まとめから外して動く物の登録簿（`Diorama.Dynamic`）に入れる。GUI の Editor では、メニュー「DeckRogue/箱庭/幕1を組む」と「書き戻す」でユーザーが目で詰められる。

**寸法**（道の座標。t は道に沿った距離、s は道と直角で＋が奥。道の向き PathYaw は−22°）
- 広さは約48×40 unit。
- 座席の帯（s −3〜+4）は高さ0の平ら。手前の段（s < −3.5）は −0.6。
- 奥のひな壇は s +5.5／+11／+18 で、高さ +1.3／+2.6／+4.5。
- 尾根（s 約+18〜22）に櫓。s 約+30 に光る霧の面。
- 手前の額縁はカメラから深さ6〜10の位置に置く。

**テクスチャ**
- 粒は25テクセル/unit。タイルは既定で **64×64（2.56 unit）**、予備が32×32。既存の act1 のタイル（32と64が混ざっている）は縮めずに25/unit でそのまま使う。
- 材質ごとに4種のタイルを `Texture2DArray` に積む。CPU の `SetPixels32` で埋め、ミップを付ける。
- 貼り方は、道の座標（PathYaw で逆回転したローカル座標）で、いちばん近い軸を1つだけ選んで投影する（3軸の混ぜはしない）。UV はテクセルの格子に合わせ、読むのはドットの縁だけ1画素なじませる方法（`fwidth`）にする。
- 天面の苔は、ドット単位のディザ（ブルーノイズの閾値をドットの中心で読む）で段々に切り替える。
- タイルの回し方は材質ごとに決める（`none`／`flipX`／`rot4`）。回してよいのは土や岩の天面のような向きのない材質だけで、草の天面は左右の反転だけにする。
- 地面は「光を受ける静かな面」にする。明暗の幅を今の約1/3にし、白い小石の粒と写実的なひびは捨てる。
- 舞台の絵（キャラ以外）は、幕1の舞台用の色表（32〜48色）へ Oklab の距離で写し、色をそろえる。キャラは写さない。

**数の上限**: 3Dの部品は約35種、半立体は約20、2Dは約15。置く数は250〜350。材質は6以下、まとめた後の Renderer は120以下。

### 2-3. キャラの座席と UI の追従（いちばん大事な作り替え）
**今の作り**: 敵・リーダー・人形の絵の位置と大きさは、UI の矩形（sprite）が決めている。舞台の板は毎フレーム矩形の四隅を読み、その座席の深さの面へ写している。演出（Squash・Puff・Lunge・Shake・Punch keepBottom・登場・撃破・逃走・人形の点灯と崩れ）は全部この矩形を動かしている。

**段1（見本）はアダプタで移る**
- sprite の矩形は「演出の取っ手」として残す。
- StageUnit は、今と同じ式を「休んでいる時の矩形との差」の形で書き直す。足元の中心 `sx=round((c0.x+c3.x)/2)`、`sy=round(c0.y)`、幅 `w=round(c3.x−c0.x)`、高さ `h=round(c1.y−c0.y)`、FeetPad×h。この差を、座席の世界の点からのずれ（カメラの横向きと上向き×px×座席の k）に変える。
- **板は回さない**（ドットは回転しないという規約を守り、old と動きを一致させる）。結果が今の値と一致することを、単体の検査で固定する。
- **板の向きは、見本ではレイアウト用のカメラの回転のまま**（カメラの方を向く）。こうするとアダプタの式は今の `ScreenToPlane` と数学的に同じになり、静止で1px 以内が自動で満たされる。縦に立てる形は段2の回り込みの時に、透視で高さを解く方法といっしょに裁定する（ボスでは上端が27px 伸びるため）。12°の傾きが影の形に与える差は無視できる。
- 演出のコード（Presenter・Tween・BattleView・BattleScreen）は1行も変えない。
- 画面の揺れ・寄り（Shake・ZoomPunch・Dolly・HitStop）は描画用のカメラだけを動かす。揺れの大きさは距離の比 r（`_dist/16.62`）を掛けて保つ。待機の漂いは場の中心を軸にごく小さく回し、座席の画面の位置のずれは2px 以内にする。撮影では切る。
- 検査: `Stage.DebugUnitBoxes()` が「矩形の画面の箱」と「板をレイアウト用のカメラで写した箱」を並べ、静止1px・演出中2px を超えたものを記録（dumplayout）に出す。

**足元の線と札の置き場**
W2 では、今の UI で重ならない値を既定にする（目安 PC 0.40・スマホ 0.52。P08 の seatfit の表で確かめる）。最終の値と、自分の札・帳面・手札の置き場は P20 が一括で決める。決める前に seatfit の表を出す。

**段2以降（見本が合格した後）**: 回り込みのカメラ・入れ物の毎フレームの追従・演出を世界の API へ移す・アダプタの撤去。

### 2-4. 光
- **本家の作法**: ドットには陰影が描き込み済み。だから光の受け方は控えめにし、形は影で読ませ、面の明暗は描き込みに任せる。
- **月（平行光）**: 左上の手前から。影あり・カスケード2。**影を落とすのは地形と大物だけ**（URP の Rendering Layers と、ライトごとの影のレイヤーで分ける）。
- **舞台の灯（スポット）**: カメラ側の上から座席の帯へ当てる。**影を落とすのはキャラの板だけ**なので、キャラの影は1方向に1本になる。キャラの固定のキーライトは、このスポットの向きと色を全員に同じに使う（シェーダの全体値）。色は中立からわずかに寒色（0.92, 0.96, 1.0）を既定にし、暖色（1.0, 0.92, 0.8）は変種 `keycolor=warm` で撮る。（W3b で既定を少し暖かい (1.0, 0.95, 0.88) に変えた。§9-2）角度と向きは、座席が画面に広がる範囲から決める。
- **木漏れ日のクッキー**: 大きく不定形な明暗を3〜5個にする。座席の帯ではコントラスト0.2以下、帯の外で強くする（等間隔の粒は作らない）。
- **逆光**: 坑口の奥の脈の青緑の点光源（影は PC だけ）と、光る霧の面。
- 影を落とす光は画面に最大3つ（スマホは2つ）。
- **環境光**: Flat をやめて Trilight（空・地平・地面の3色）にする。遮蔽は頂点色の AO と SSAO（PC だけ）。ライトマップは見本では焼かない。
- **霧**: 距離の霧（元の値×r を1か所で計算して書く。何度も掛け重ねない）と高さの霧、光る霧の面、光の筋。
- **技の光**: `StageFx.HitLight`。同時に3つまで、影を付けるのは大きい当たりだけ。2Dの斬撃の筋は UI のまま残す。
- **光の値の置き場**: 幕ごとの設計図に持つ。ファイルは持ち主ごとに分け、`StageLook` が順に重ねて読む。
  - `look_act1.json`（舞台の光・霧・後処理・材質ごとの受光。持ち主 P22）
  - `look_act1.char.json`（キャラの光。P23）
  - `look_act1.dof.json`（ぼかし。P24）
  - `look_act1.phone.json`（スマホの段。P31）
- 見本の舞台では PalOf・HeroAmbient・VignetteLift・CharAmbient を使わない（`stage=old` では今のまま残る）。

### 2-5. シェーダ
全部のプロパティを UnityPerMaterial に入れ、SRP Batcher に載せる。自前の切り替えは `multi_compile_local`（`_UV_MESH`・`_ALPHATEST_ON` の2つ）か float の分岐にする。`shader_feature` は使わない（ビルドで版が削られるため）。URP の multi_compile は、ローカルの URP 17.6 の `Lit.shader` からそのまま写す。

- **StageModule**（地形・3Dの部品・半立体）
  - 光は `albedo×(環境光＋_Receive×直接光)` の形で受け、影は `_ShadowStrength` で別に効かせる。`_Receive` の既定は、地形0.8・半立体0.35・札0.25。
  - 貼り方は §2-2 のとおり（道の座標で1軸投影・格子合わせ・苔のディザ）。
  - 法線は `tex×2−1` で自分でほどく（`UnpackNormal` は使わない）。
- **StageUnitLit**（キャラの板）
  - 固定のキーライト×受光率 `_Receive`＋上下の環境光＋主役の持ち上げ（`heroLift`）。
  - 法線はドットの中心で読む。`_KeyFlip`（画像ファイルを左右反転した絵のために、キーの向きの X を反転する）。
  - 発光マスク `_EmissionMap`。輪郭の持ち上げ `_OutlineFloor`。`_WhiteCap` は既定1.0（使わない）。
  - `_Flash`・`_Dissolve`・リム・霧は今の式を写す。
  - 影を落とす（ShadowCaster）。影を受けるのは既定で切る。受光0で平らな色に戻る。
- **StageShaft**（光の筋・霧の面・地面の光の輪）: 加算・深度で縁を消す・霧に沈む。
- **TiltShift**: §2-6。

### 2-6. 後処理
- Volume は幕ごとに StageLook が組む。トーンマップは ACES と Neutral を撮り比べる。
- ブルームは閾値1.0前後。周辺減光は座席の帯の外側から効かせる（0.25）。フィルムグレインと、いつも掛かる色収差はやめる。
- **ティルトシフト（自作。Render Graph）**: 座席の帯（`SeatDepthRange`＋余白）ではぼかしを0にし、帯の外で急に強める。手前はにじみ出しと、前景の層の合成を行う。上限は PC 24px・スマホ12px。深度テクスチャは `requiresDepthTexture=true` で必ず作り、中間テクスチャ（`requiresIntermediateTexture`）を使う。崩れた時は `dof=urp` で URP の Bokeh に戻せるようにしておく。強さは、S-quad で奥の敵が読めることを先に守って決める。
- **AA**: MSAA（PC は4x、スマホは切る）。キャラの板はアルファで切っているので、中のドットはぼけない。半立体の葉の縁は alpha-to-coverage を試す。FXAA と SMAA は使わない。
- SSAO は PC だけ。

### 2-7. スマホ
- 同じ構図のまま段を落とす。影つきの光は2つ（影512）、逆光の影なし、SSAO なし、MSAA なし、ぼかしは半解像度で12px、水面の反射なし。
- URP のアセットとレンダラーをスマホ用に分ける。`tier=phone` を付けると、PC でもその品質レベルと `look_act1.phone.json` に切り替わる。
- 重い時に落とす順: 光の筋と霧の面 → 影つきの逆光 → SSAO → ぼかしの段数。解像度は下げない。

### 2-8. 今のコードからの移り方
- **M0（W1）**: 見た目を1画素も変えない。Stage.cs を分け、新しい物を「つながない状態」で置く。
- **M1（W2）**: Linear へ切り替え、`stage=diorama` で箱庭を立てる。キャラはアダプタと光を受ける板へ移し、技の光を付ける。`stage=old` の画を「Linear 版の今」として撮り直し、新しい比較の元にする。
- **M2（W3）**: UI の夜色・足元の線・手札の沈め、光・地面・ぼかし・キャラを詰める。
- **M3（合格の後）**: 幕1の既定を箱庭に切り替え、幕2・3を作り直す。旧 Paint を退役させる。

## 7. リスク

1. **Linear で色がずれる**（霧・混ぜ合わせ・ブルーム・UI の半透明・TMP）。
   → W1 は Gamma のまま画素一致を取り、W2 で Linear 版の今を比べる元にする。戻し方は2段（受光0／Revert）。P21 が UI を合わせる。
2. **レーンがコンパイルできない**。
   → W0 の dotnet の型検査と約束の骨組みで、型のずれを波の前に潰す。シェーダはオフラインで実際に変換する。キーワードの取りこぼしは `multi_compile_local` と player.log の grep で拾う。
3. **撮影が決定的にならない**。
   → `-det` を Awake で掛け、captureFramerate を戻す所も det に従わせ、門の比較は1行ごとに起動して撮る。
4. **アダプタのずれ**。
   → 今の式を写して回さない。単体の検査と DebugUnitBoxes で毎回見る。予備の包み P33 を置く。
5. **足元の線を下げると札と重なる**。
   → seatfit の表を先に出し、W2 は重ならない既定にする。最終は P20 が表で決める。目標の62〜68%に届かない時は、届く一番低い線と理由を報告する。
6. **コードの3Dが「古い3D」に見える**。
   → 道の座標で1軸投影・面の平らな押し出し・格子合わせ・苔のディザ・自然物は半立体・幹は2通り。W2 で崖を1:1で本家と並べる。FBX で差し替える口も残す。
7. **二重の陰影で泥やプラスチックのように見える**。
   → 材質ごとに受光を分け、影は別の値にし、キャラは固定のキーだけ（受光は低め）にする。受光0に戻すスイッチを持つ。
8. **影が2本落ちる・暖色で画風が崩れる**。
   → Rendering Layers でキャラの影はスポットからだけにする。キーは中立色を既定にし、暖色は変種。
9. **主人公が暗い・画像ファイルを左右反転した絵と光の向きが矛盾する**。
   → heroLift と発光マスク、`_KeyFlip`。直らない絵だけ塗り直す。⑧を地面との比に置き換えた。
10. **PixelLab の新しい機能が動かない・継ぎ目がそろわない**。

    → 縮めた見本で大きさだけを先に決め、清書は選ばれた時だけ作る。
12. **48にしてもボスとの比が本家（3.5〜4.3倍）に届かない**。
    → 見本では比を見せるだけにする。足りなければ段2で幕ボスの描き直しを判断する。
13. **自作のぼかしが縁や半透明で崩れる・深度テクスチャが無い**。
    → `requiresDepthTexture`・中間テクスチャ・`dof=urp` の逃げ道。
14. **ライトマップが無いので間接光が薄い**。
    → 頂点色の AO・SSAO・Trilight。足りなければ段2で焼く道を選ぶ。
15. **S25 を測れない・計測でセーブを消す**。
    → 別の applicationId・Delete を飛ばす・終わらない戦闘・手順書。保留の門にする。
16. **夜色で「絵本」の肌が弱まる・手札の数字が読みにくくなる**。
    → ui=paper も撮り、ユーザーが選ぶ。下端から36px を自動で検査する。
17. **彩度の上限は裁定に入っていない**。
    → 既定は「入れない」にし、W5 で確かめる。
18. **本家の画像は著作物**。
    → キャッシュに置いて送るだけにする。トレーラーはリンクだけ。
19. **見本は1舞台だけ**。
    → 幕2・3の作り直しは段2の規模（見込み）。

### 9-2 計画から変えたこと（理由つき）
1. **主人公は 48 を既定**（`hd2d=slice` に `herodots=48`）。ユーザーの方針「本家っぽく」④。62 は `herodots=62` で撮れる。48 の清書（P23 の手順4）は PixelLab の月の枠が 27.45 しか無いので 10/7 の後。
2. **幹と根は半立体が既定**（`trunk=relief`）。方針⑤（自然物は半立体・人工物と地形は3D）で W2 の問い①に答えが出た。3Dの筒は `trunk=mesh`。
3. **キャラのキーの色は少し暖かく** [1.0, 0.95, 0.88]（§2-4 の既定は中立 [0.92, 0.96, 1.0]）。本家の夜でもキャラの白は暖かい（`honke-color.md` §5。W3 で狼の白が b* −2 に冷えた）。`keycolor=warm` の値 [1.0, 0.92, 0.8] は変えていない。
4. **旗 `look=` は「丸ごとの差し替え」でなく「幕の設計図の上に重ねる変種」**（W3 P22。`+` で複数）。光の設計図に `"layout"` を書けば別の箱庭の設計図で組める（W3b）。比べる変種は `Resources/Stage/look_act1_*.json`（約30）。
5. **足元の線**: §2-3 の目安 PC 0.40 は自分の札が主人公の足元を隠すので W2 は 0.42、W3 で手札を沈めて **PC 0.41・スマホ 0.51**（`StageCamera`）。主人公の足元は画面の上から約 61.5%（§1-1 の目標 62〜68% に 0.5% 届かない）。旗 `groundline` は「世界の原点を画面の下から何割」で、§1-1 の「上から何%」とは別の物差し。
6. **③ 中央÷端**: 計画の手段（舞台の灯・周辺減光）では 2.5 で止まったので、**舞台だけの周辺減光 `stageVignette`**（`StageModule`・`StageShaft` の全体値。キャラと UI には掛からない）を足した（W3b P22）。URP の周辺減光はキャラにも掛かるので 0.15 に弱めた。
7. **本家の色彩**（計画に無かった。ユーザーの依頼・W3 の統合）: 色の設計書 `honke-color.md`／`.json`・舞台だけの色の寄せ `envGrade`・物差し `scripts/hd2d-color.py`（Oklab の8つ）と `scripts/hd2d-honke-targets.py`（21項目）。
8. **地面の模様**: §2-2 の「明暗の幅を今の約1/3」は奥の段だけにした。座席の帯は明暗 0.6 の草・コード生成の踏み固めた土・地面の小札（新しい kind `litter`・背丈12ドット以下・39枚）（ユーザー「本家っぽく」⑧）。
9. **輪郭**: `_OutlineFloor` に加えて、画面の最暗色の目標 `outlineTarget`（27）から後処理を逆にたどって `_BlackLift` を絵ごとに解く（P23）。このはの暗い色の持ち上げ `_ShadeLift`・キャラの色の掛け算 `_CharTint`（舞台の色の膜を打ち消す）も足した。`_WhiteCap` は既定 1.0 のまま。
10. **`_KeyFlip` の選び方**: 「画像ファイルを左右反転した絵」でなく、art-lint が測った「光が右から描き込まれた絵」（`keyflip.json` の `lightFromRight`）。反転の表は16枚中9枚が左からの光だった（W3 P23）。
11. **ぼかし**: ピントの帯を深さでなく道の座標の帯に（`focus: path`・s −3〜5.5）・薄いレンズの形（`curve: lens`）。上限は本家の測りから奥 10px・手前 20px（§2-6 の PC 24px・スマホ 12px は上限の器として残る）。
12. **PixelLab**: create-tiles-pro は案内線が残るので不採用。タイルは pixflux 160 → 中央 128 → 64×4（1生成で4種）。塗り直しは要らなかった。

14. **物差しの読み替え**: ①画素一致の門は「差が2レベルを超える画素が 0.1% 以下」（ビルドが変わると旧舞台の地面の縁の描く順が入れ替わる・W0）②§1-2 の4「演出中 2px」は今の舞台（old）でも満たさない（Squash などで矩形の縦横比が変わるのに板は絵の比を保つ）＝「old との差 ≦1px」で読む（W2）③⑥はキャラの板を除いて測る（`m6_nb`・W3）。
