## 1. 共通の約束（静止画）

- **輝度** L = 0.2126R + 0.7152G + 0.0722B（sRGB の 0〜255。targets の `measure.py`・`hd2d-measure.py` と同じ）。動画の道具だけは元の道具どおり 0.299R + 0.587G + 0.114B。
- **舞台の画素** = UI なしの画（`<場面>-hideui-1.png`）の全画素。本家は `metrics.json` の UI の矩形を除く（`measure.py` と同じ）。UI ありの画しか無い場面は layout.json の UI の矩形で除き、舞台の物差しは合否を付けない（≈）。
- **キャラの型** = `<場面>-unitsonly-1.png`（マゼンタ以外）を 4px 太らせた物。無ければ同じフォルダの unitsonly から借りる（同じキャラ・同じ板 ±0.6px・同じ画面・同じ時刻 ±0.05 秒＝DET=1 は場面をまたいで同じ画素。三周目の `hd2d-r3-targets.py` と同じ借り方）。変種の行（`PC-T2-exp040-hideui` など）は `PC-T2-squire-unitsonly` から借りる。
- **主人公の足元** = layout.json の `stage.camera.seats` の player（無ければ板の矩形の下端）。本家は `metrics.json` の `hero_feet`。
- **長さ** は PC の px（1920×1080・座席で 1 ドット＝4px）。スマホ相当（1920×886）は主人公の 1 ドットの px ÷ 4 ＝ sc（約 0.79）で縮め、本家は H/1080 で縮める。
- 場面の名前は `<PC|PH>-T2-<場面>`（試し）・`<PC|PH>-S2-<場面>`（本番）。末尾の `-hideui`・`-unitsonly`・`-uionly` を付けても付けなくても同じ場面として読む。

## 4. 動き（`scripts/hd2d-motion/`）

**判定は動画の左右並べ（本家 clip｜うちの mp4・5 場面 × 2〜4 秒・1 本 15〜20 秒）を目で見て下す**（裁定 3）。数字は motion.md §7 の目安と比べる補助。

**連写の 1 コマは 1/60 秒ではない**（2026-10-03 反証の直し）。Autopilot の連写のループ（`play=`・`usegear=`・`endplay=`・`fire=`・`entershots=`）は every フレーム待って撮り、撮る前に 1 フレーム・撮った後に 3 フレーム回す＝**1 コマ = every + 4 フレーム**（DET=1 の captureFramerate=60 で 1 フレーム = 1/60 秒。`playevery=1` でも 5 フレーム = 1/12 秒）。1 枚目は命令（札を出す・手番を終える・登場を鳴らす）の every + 1 フレーム後＝**札を出す前の盤面ではない**。連写の後ろには 1 枚撮りの `state-combat` が同じ連番で付く（間隔が飛ぶ）。
何枚目が何秒かは `scripts/hd2d-motion/seq.py` が読む: ①`<名前>-<n>.layout.json`（dumplayout=1）の `frame`（Time.frameCount）と `name` ②無ければ `<名前>.log` の撮った名前の並び＋every（STATE か、`scripts/hd2d-states/*.txt` の同じ名前の行の STATE か、`--every N`）③どちらも無ければ `--every N`（pshots の連写）か `--fps F`（素の連番）を書かないと止まる。log の `ut=` は Time.unscaledTime＝実時間（captureFramerate は deltaTime だけを固定する）なので使わない。秒は全部「連写の 1 枚目 = 0 秒」（mp4 の 0 秒と同じ）。`state-*` は外す。1/60 秒ごとに撮るには Autopilot の連写に「撮った後を待たない口」が要る（持ち場の外＝統合へ）。

1. 撮る: `s2-dio23.txt` の `PC-T2-attack`（A 通常の大きい当たり・24 枚 = 2 秒）・`PC-T2-x`（B ブースト級 = X 札 `green_x_vine_flurry`・36 枚 = 3 秒）・`PC-T2-kill`（幕ボスのとどめ・30 枚 = 2.5 秒）・`PC-T2-spell`（C 呪文・全体 `green_earth_roar`・30 枚）・`PC-T2-enemy`（D 1 ターン目の普通の攻撃 = 光らない対照・42 枚 = 3.5 秒）・`PC-T2-enemy-big`（D 大亀の大薙ぎ = 予告つき大技。`endturn=2` で 3 ターン目・42 枚）・`PC-T2-idle`（E 待機 = 戦闘の始まりから 60 枚 = 5 秒。登場の演出の後の 1〜5 秒 = 13〜60 枚目を待機として測る）。秒は計画 §4 の字の秒（計画の「120 コマ」などは 1/60 秒の読みの数）。各場面の **`-pre`** は同じ STATE から `play=`／`endplay=` を抜いた 1 枚撮り＝出す前の盤面（数字の基準）。全部 `DET=1`。
2. mp4 にする: `scripts/hd2d-motion/frames2mp4.sh <撮影のフォルダ> PC-T2-attack`（既定の出力 `~/.cache/deck-rogue/hd2d-stage2/motion/ours/PC-T2-attack.mp4`）。seq.py が読んだ秒で 1 コマずつの長さを書いた一覧を ffmpeg の concat に渡す＝**本当の速さの 60fps**（同じコマが 5 フレームずつ続く）。layout.json も STATE も無い時は `EVERY=N`、素の連番は `FPS=F`。
3. 並べる: `scripts/hd2d-motion/sbs.sh -l <一覧.txt> <出力.mp4>`（一覧の書式と motion.md §7 の 5 場面の例は `sbs.sh` の頭）。1 組だけなら `sbs.sh <本家の動画> <開始秒> <長さ秒> <うちの mp4> <出力.mp4>`。短い側は最後のコマで止めて長さをそろえ、左上に「本家」「うち」を焼く。
4. 数字: `python3 scripts/hd2d-motion/motion_metrics.py <撮影のフォルダ> PC-T2-attack [--region wall=x0,y0,x1,y1] [--region floor=…] [--idle 1,4]`（待機は `PC-T2-idle --idle 1,4`）。基準は同じフォルダの `<名前>-pre-1.png` を自動で読む（無ければ連写の 1 枚目だけ＝命令の every+1 フレーム後・当たりの光の前。`--base-image` で書ける）。コマは 1 枚ずつ読んで捨てる（300 枚でもメモリは 1 コマぶん）。連写は 1 コマ 1/12 秒なので、光と保つの秒は 1 コマ（0.08 秒）の粗さを持つ。`seq.py <フォルダ> <名前>` で何枚目が何秒かだけを確かめられる。

| 数字 | 式（motion.md と同じ） | 目安 | 本家（この道具で測った値／motion.md） |
|---|---|---|---|
| 寄りの間の壁 ×N | カットからカットまで（同じカメラ）の壁の矩形の最大 ÷ 最大の後の最小 | ≥2 | 松明の洞窟 6.667〜7.55s: **×2.50**／×2.27（6.90s ÷ 7.48s） |
| 暖色の割合 | 壁の矩形で R − B > 20 の画素の割合の最大 | ≥0.6（幕2） | 0.939／0.91 |
| 技の光の長さ・保つ | 壁が「最小 + (最大 − 最小) × 0.1」「× 0.8」を超える秒 | 0.9 秒・保つ 0.3 秒 | 0.68・0.32／0.95・0.35 |
| 暗転 | 最初の光の山より前（0.1 秒より後）の 全体・床 の最小 ÷ 基準（動画は最初の 6 コマ = 0.1 秒の中央値・連写は `-pre` の 1 枚撮りか連写の 1 枚目） | ×0.5 | 全体 ×0.74・床 ×0.40／×0.66・×0.30（区間の取り方の差） |
| 待機のカメラ | 奥の帯（x 600〜1320・y 60〜300）の位相相関のずれの幅 | 0 | 0.00px（`sway.py`・夜の森 80〜81s） |

- **カット** = 前のコマとの明るさの差の平均が 30 を超え、かつ形の相関（位相相関の山）が 0.7 より低い所（光の閃きは明るさだけ変わる）。本家の YouTube の動画は暗い→暗いの切り戻しを圧縮で拾えないことがあるので、`--zoom 開始秒,終わり秒` で寄りの区間を書ける。うちの連写は圧縮が無いので切り戻しも拾える。
- **矩形の既定**は本家 松明の洞窟の「右の壁」（x 900〜1900・y 120〜520）と「床 中央」（x 500〜1400・y 760〜1000）。うちの寄りの画では壁が入る場所が変わるので、撮った 1 枚目を見て `--region` を書き直す（寄りの向きはレーン M が決める＝「対象の背後の壁が画面の右半分」）。
- `fine.py`・`sway.py` は `~/.cache/deck-rogue/hd2d-stage2/motion/tools/` の写し（動画の置き場を決め打ちしない・`--region`・`--csv`・連番の画 `<フォルダ>/<名前>-%d.png` を足した）。連番は seq.py の秒で 60fps に並べ直してから測る（1 行 = 1/60 秒のまま。同じコマが続く）。
- 連写の 1 コマの間にキャラも動くので、前のコマとの明るさの差は動画より大きく出る。カットは形の相関（0.7）で見分ける。

## 5. 画素比べ（`hd2d-pixdiff.py`）

- 規約: 値の差（RGB の最大）が 2 を超える画素の割合が 0.1% 以下 = 同じ画。合格 = 一覧の全枚が同じ画（計画 §1・§3 手順 1）。
- 順番（計画 §3 手順 1）: まず幕1 の組（`s2-slice`・`s2-k0v`・`s2-ui`・`s2-regress`・`s2-regress-ph`）、次に今の舞台の組（`s2-old`・`s2-old23`・`s2-regress-old`・`s2-regress-old-ph`）と旗なし起動（`s2-apk`・`s2-screens`）、最後に `s2-mixed`。
- `s2-mixed` は名前が違う（`PC-M2-squire` ↔ `PC-O2-squire` など）ので別名の対で比べる: `python3 scripts/hd2d-pixdiff.py <s2-base>/s2-old23 <s2-after>/s2-mixed --pairs @mixed-old23`（ほかに `@mixed-apk`＝基準 s2-apk・`@mixed-slice`＝基準 s2-slice）。対は `s2-mixed.txt` の頭の「対」の写し。`-nolayout` の 2 行は `@mixed-nolayout`（幕2/3 の設計図と光を置く前だけ今の舞台と同じ画が合格。置いた後は箱庭になるので比べない）。
- `--specks` は 40×40 に収まり 800 画素以下の差の塊（月の塵の粒）を除いた割合でも判定する。scipy が無くても同じ結果になる素朴な数え方を持つ（差の画素が 20 万を超える時は粒を数えない＝下書きと同じ）。
- 対なし（比べる側に画が無い = 撮り損ね）は既定では不合格に数えない（下書きと同じ）。`--strict` で数える。終了コード 0 = 全枚合格・1 = 不合格あり・2 = 対が 0 枚。
