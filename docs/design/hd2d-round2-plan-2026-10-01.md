## 0. 1回目の計画から何を変えたか（反証の要点）

1回目の計画のままだと、見劣りは **3〜3.5 どまり**という反証が2本来た。受け入れた主な点は次の6つ。

1. **霧の帯の作り方を変える。** 1回目は「高さの霧（低い所ほど濃い）を道の座標 s で置く」だった。新しいカメラで光線を飛ばし直すと、いちばん明るい所は **行≈446（主人公の頭〜首の後ろ）**、帯の幅は行330〜578 の約250px、しかも **行≈327 に箱庭の奥の端の段差**が出る（`honke/fog_newcam.py`・`honke/fog_plan_shape.png`）。→ **帯は距離の霧（奥ほど明るい）で作る。高さの霧は地面のもや（濃さ 0.3）に下げる。** 奥の端は、地面を霧の満ちる深さまで伸ばし、カメラの奥に霧に沈む板（背景の板）を置いて消す（K2・K10）。
2. **上の真ん中は暗くしない。** 本家 ot16 の中央の列（x900〜1300）の行0〜300 は **80〜101＝頂点の 0.55〜0.65 倍**で、暗いのは両端（x0〜300 は 20〜33・x1600〜1920 は 8〜19）だけ。→ 上の減光は両端だけ。上の真ん中は、霧に沈んだ幹と針葉の枝の影絵で埋める（K4）。
3. **木の種類を変える。** 手持ちの木の絵（oak・oak2・giant・pine2・canopy_1〜3）は「木全体が画面に収まる小さな丸い木」で、公園の木に見える（`honke/mock_plan_PC_wolf.png`・`honke/trees.png`）。→ 霧の帯と右端には **幹だけ**（画面の上を突き抜ける 280 ドットの幹をコード生成）。黄緑の canopy_1〜3 はそのまま使わない（K4・K11）。
4. **先に試しのビルドを1回撮る。** 22°・5° は一度も撮っていない（W5 の変種の最低は 22°・10°）。上半分・奥の端・地面のぼけは新しいカメラで初めて写る。→ **カメラと霧の方式だけの試しのビルド（撮影12枚・約10分）**で形を見てから、残りの値を決める（K10・§3）。直しの輪も1回→最大2回にする。
5. **今の舞台（幕2/3）へ漏れる所を塞ぐ。** 束の `pitch=auto` は読めない（`HD2DFlags.cs` 386行は数しか読まない）ので、幕1→幕2 で見下ろし 5° が残る。待機のコマ・月の塵・杖の光・接地影の絵も、今の舞台に効いてしまう書き方だった。→ 束は数で書く（`pitch=12`）。新しい振る舞いは全部「箱庭の時だけ」の枝に入れ、**旗を書かない幕2/3 の撮影を W5 の直し（apkfix）の画と画素で比べる**（§3-5）。
6. **門⑧の本当の危険は敵の側。** 門⑧は「差 15 以上か比 1.4 以上（どちら向きでも）」（`scripts/hd2d-measure.py` 616行）。主人公は明るくすれば通る。危ないのは **オーガ（W5 で体 89・足元の輪 64）**で、地面を 90 前後へ上げると体と輪が同じ明るさになり割れる。→ 本家どおり**大きい敵は暗い体**（本家の魔物の体の中央値 55）にする（K7）。

受け入れなかった指摘・一部だけ受け入れた指摘は末尾「受け入れなかった指摘」に理由を書いた。

## 受け入れなかった指摘（と、一部だけ受け入れた指摘）

| 指摘 | 扱い | 理由 |
|---|---|---|
| 距離の霧は「指数で満ちる形」にする（反証1-1） | **一部だけ**: 距離の霧を帯の主にするのは受け入れた。形は**線形のまま** start を座席の奥（深さ 20）に置く | 指数の霧は深さ 0 から掛かるので、座席とキャラにも霧がかかる（exp2 で深さ 20 に約3割）。線形なら座席はきれいなまま、地平線で満ちる。形の違いは試しのビルドの3変種（start・end・lobe power）で詰める。なお URP の霧の変種は GraphicsSettings の `m_FogKeep*` が全部1なので、指数にしても描ける（逃げ道として残る） |
| 段3 の地面を s150〜200 まで伸ばす（反証1-2） | **別の手で**: 地面は s70 まで、奥はカメラに付く背景の板（深さ 140・霧で満ちる）で覆う | 道の向き −22° のせいで、s を伸ばすほど画面の左へ寄る（s120 は t −8〜10 で x −114〜264）。画面の右の地平線までは地面では覆えない。カメラに付く板なら画面の全幅を覆い、霧の芯（lobe）で「真ん中が明るく端が暗い」形も同時に出る |
| camera.background を霧の芯の色にする（反証1-2） | **一部だけ**: 背景の色は霧の端の暗い色 [0.06,0.09,0.12] | 背景の板が覆うので背景の色はほぼ写らない。写った時（板の失敗）に真ん中が明るい無地の帯になるより、暗い方が目立たない |
| 主人公の見積もりで「門⑧に要る約119」（反証1-5） | **一部だけ**: 持ち上げ 2.0 は受け入れた。門⑧の心配の向きは直した | 門⑧は「差 15 以上**か**比 1.4 以上（どちら向きでも）」（`hd2d-measure.py` 616行）。主人公 118 と輪 77〜91 なら差で通る。本当に危ないのはオーガ（W5 で体 89・輪 64）で、そちらを暗くする手を足した（K7・レーン E の1） |

| 霧の帯の幹は「主人公と1体目の敵の間」と「画面の外側」だけ（反証1-7） | **一部だけ**: 太い幹はそのとおり。細く霧に沈めた幹は 3〜4体の座席の後ろ（x1700〜1800）に置く | 1〜4体の足元の x の ±130px は x996〜1902 をほぼ全部覆い、画面の右半分に幹が1本も無くなる。本家 ot16 も主人公の ±75px（x1135・1285）に細い幹がある。霧の 0.7 倍より明るく沈めれば頭の輪郭は割らない |
| 座席ごとの光の池の焼き直しの条件（反証2） | **不要になった** | 座席ごとの光の池は入れないことにした（K7・K14）。門③の読み方を聞いてから |
| 宝石の点光源はコマごとの UV の表を持つ（反証2） | **簡単な方**: 待機以外のコマでは強さ 0.3 倍 | 攻撃4コマ・待機8コマの UV を表にする手間に比べ、振りの間（0.35秒）だけ弱めれば宙に残る光は目立たない。R1 のコマ送りで確かめる |
| レーンごとに git worktree で型検査を分ける（反証2） | **受け入れない**（代わりに名前の印と grep） | 統合のビルドは1つの作業ツリーで行い、レーンのファイルは重ならない。worktree に分けると統合でまとめ直す手間とぶつかりが増える。名前がぶつかるのは partial の新しいメンバーだけなので、印と grep で防げる |
