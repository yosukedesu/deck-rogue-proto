**PixelLab は 0 回**（10/7 まで呼ばない）。今ある絵（`Art/props/act3_*`・`Art/tiles/act3_*`）と幕1 の道具だけで作った。
今の舞台（`stage=old`）が読む `Art/props`・`Art/tiles`、幕1 の `Art/stage/act1`・`docs/pixellab/hd2d-act1/`、幕2 の `Art/stage/act2`・`docs/pixellab/hd2d-act2/` は **1 バイトも変えていない**（読むだけ・import するだけ。幕2 の `gen_items.py` は手本にしただけで import しない）。

**直しの番（2026-10-03・反証役の指摘 5 件）で変えた所**（下の各節にも書いた）:
1. 石積みの 4 種の左右の端の帯を a の帯にそろえた（`unify_edges`）＝別の種どうし・反転どうしを並べても継ぎ目が出ない。門「別の種どうしの継ぎ目」を足した（`cross_seams`）。side_step は stone_d だけにした（stone_b は下の目地の帯が厚く、上下に並べると境が目立った）
2. 天面の石板の横の目地を、石板 1 枚ごとに「砂で埋まった目地」にして、横幅いっぱいの線を切った。行 0 の上の縁の光は付けない
3. 光る所の中心の高さを index.json の relief に `glow` として書いた（設計図の暈と lights の at はこれを使う）
4. 計画から変えた所の理由を書いた（館の壁を dirt でなく cliff_a にした理由など）。柱の明るさを計画の約 135 に、座席の床の画面の細かさを計画の 20〜40 に入れた
5. 光の向きに左右が入る絵と小札に `flipOk: false` を書いた（左右反転して置かない）

### タイル（`index.json` の `materials`。どれも calm 済み＝読み込み側で `calm=1・sat=1`）

直す前は 1 枚ごとにしか継いでいなかったので、横に回した種や別の元どうしを並べると端の列が合わなかった（side_wall の a|c で端の差 56・中の差 10＝5.97 倍。side_step 5.32 倍）。

天面は最初 tile-calm で作ったが、元の 4 枚の模様（煉瓦・ひびの十字）が種ごとに違い、混ぜて敷くとつぎはぎに見えたので石板のコード生成へ移した（`CALM` は空・道は残してある）。

石板のコード生成（`slab_floor`。天面 4 材質）: 段の高さは 4 種で同じ（境をまたぐ石板の上下の目地が隣の種と合うのはこの形だけ）。各段の縦の目地は乱数で互い違い（running bond）。
**直しの番**: 直す前は横の目地（行 31・63）がどの種でも横幅いっぱいに通り、床に 32 テクセルおきのまっすぐな横線が切れ目なく並んだ（反証の指摘 2）。
- 段の高さを種ごとに変える案は捨てた: 境をまたぐ石板の上下の目地が隣の種と合わなくなる。合わせるには境の帯だけ段をそろえ、内側との間に上から下まで通る縦の目地が要る。試すと、見下ろしの画面の模型（横 4px・縦 0.5px／テクセル）で縦の目地が 64 ごとにそろって柵のような縦線になり、直す前より規則的に見えた
- 採った形: 横の目地を石板 1 枚ごとの区切りで「砂で埋まった目地」（暗さ 0.22 倍・下の縁の影と次の段の上の縁の光も同じ倍）にし、1 本の横の目地の暗い所を横幅の 3〜6 割未満に収めた＝線が石板 1〜2 枚ごとに切れる。縦の目地（石の形が読める所）は全部暗いまま。行 0 の上の縁の光は付けない（上のタイルは別の種で、その行 63 の目地が埋まっているかが分からない）
- 反証の「行 63 の目地は中の目地より暗い・境の段差は中の差の 8 倍」は当たらない: 行 31 と行 63 は直す前も同じ暗さ（どちらも 84）で、境の段差 27.9 は中の行 31→32 の段差 27.9 と同じ＝境は継ぎ目でなく普通の目地。8 倍は目地の段差を石の面どうしの差 3.5 と比べた値。門は「境の段差 ÷ 中の目地の段差」（`tbJoint`）にした（今 0.4〜0.6）
