# レリック設計案 v2（2026-08-24 改訂・実装はゲートA通過後）

Phase B（ルール完成＝Unity移植の凍結条件）の設計文書。承認後に実装する。
v1からの変更: ①取得経路を再検討（焚き火二択案は差し戻し→複数案併記） ②「二の符の帯」（伏せ同時2枚）は
**レリックから除外しリーダースキル候補へ移管**（ユーザー判断: 伏せ軸はランの運でなく開始時の戦略選択に置く）
③第一弾リストは候補メニューを拡充して選定し直す。

## 1. 目的

- ランに**戦闘間で持続する個性**を足す（現状はカードピックのみ。ラン同士が似がち）
- 既存の焚き火を**意思決定**に変える（回復かレリックか）
- StSで実証済みの「ビルドが化ける瞬間」をつくる

## 2. 取得経路【確定: A. エリート挑戦オファー（2026-08-24決定）】

- **2・5・8戦目の戦闘前**にオファー: 「⚔️ 強個体の気配がする——挑むか？」→ **挑む（エリート戦）／避ける（通常戦）** のopt-in
  - 固定戦目にする理由: 予見できるリスク計画（StSのマップでエリートが見える思想）。各tierに1回ずつ、焚き火（3/6/9後）とボス前を避けた配置
- **エリート補正**: 同じ敵/編成に 強化+2・HP×1.35・👑表示。フレーバー「強個体」
- **報酬**: 勝てば**レリック3択から1つ**（通常のカード報酬に加えて）。負ければ当然ラン終了＝リスクは本物
- 1ラン最大3個・候補列はラン開始時にシードから決定（リプレイ再現性）・同名は候補から除外
- simボット方針: HP60%以上なら挑む、未満なら避ける

## 2.5 リーダースキルへ移管する案件【保留・記録のみ（2026-08-24決定）】

- **伏せ同時2枚**（旧・二の符の帯）: レリックではなく**リーダーの個性④伏せ枠数**として設計する。
  「伏せを軸に戦う」ビルド意図を開始時に宣言できる形が正しい（2026-08-24ユーザー判断）。
  受け皿候補: ⓐ新リーダー（伏せ特化の第5リーダー） ⓑ既存リーダーの個性に追加 — **どちらにするかはゲートA後に設計**。
  実装時は確定済みルール表「リーダーの個性」「伏せ枚数」を先に更新する。

## 3. 実装アーキテクチャ（3カテゴリ）

| カテゴリ | 仕組み | 例 |
|---|---|---|
| A. フック型 | **リーダーパッシブと同じ機構**：DeclarativeEffect を持つ不可視の置物として戦闘開始時に自動注入（`buildLeaderPassive` の相似形。エンジン変更ほぼゼロ） | 毎ターン氷壁+1、戦闘開始時ドロー+2 |
| B. ラン定数型 | RunState のフィールドを取得時に書き換え | 最大HP+8、勝利時回復+5 |
| C. ルール改変型 | エンジンのフラグを参照する少数精鋭 | **伏せ同時2枚**（確定済みルール表「伏せ枚数（レリック拡張余地）」の回収） |

- データは `data/relics.json`（id/name/sprite/description/カテゴリ/効果）
- 新トリガーは `onCombatStart` のみ追加（既存の onTurnStart/onAttacked 等に相乗り）
- UI：トップバーにレリックアイコン列＋ホバーで説明（キーワード吹き出しの流用）

## 5. sim ボット方針

- パッシブ効果はボット変更不要（状態に乗るだけ）
- 焚き火の選択ポリシー：HPが50%未満なら回復、以上ならレリック（先頭を取得）
- 検証観点：レリック導入後の走破率が帯（8〜15%）を超えないか／「二の符の帯」の発動率変化

## 6. テスト方針（仕様＝テスト）

- 取得：焚き火でレリック選択→回復なし＋所持に追加／回復選択→従来通り
- A型：注入された置物がリーダーパッシブと共存して発火する
- C型：二の符の帯で2枚目が伏せられる／未所持では従来通り1枚制限
- 決定論：同シード＝同レリック候補列
