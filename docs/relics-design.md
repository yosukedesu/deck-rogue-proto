# レリック設計案 v1（2026-08-24 起案・実装はゲートA通過後）

Phase B（ルール完成＝Unity移植の凍結条件）の設計文書。承認後に実装する。

## 1. 目的

- ランに**戦闘間で持続する個性**を足す（現状はカードピックのみ。ラン同士が似がち）
- 既存の焚き火を**意思決定**に変える（回復かレリックか）
- StSで実証済みの「ビルドが化ける瞬間」をつくる

## 2. 取得経路（提案：焚き火の選択肢化）

3・6・9戦目クリア後の焚き火を**「回復（最大HPの30%） or レリック（3択から1つ）」**の二択にする。

- HP経済と直結した本物のジレンマ（瀕死でレリックを取る欲張りが事故る＝StSの休憩vs鍛錬と同型）
- 新しい画面・マップ不要。既存フローの改修だけで済む＝実装最小
- 1ラン最大3個。レリック候補はラン開始時にシードから決定（リプレイ再現性維持）
- 将来の拡張口：エリート挑戦オファー報酬・イベント（Phase B のスコープ決定次第）

## 3. 実装アーキテクチャ（3カテゴリ）

| カテゴリ | 仕組み | 例 |
|---|---|---|
| A. フック型 | **リーダーパッシブと同じ機構**：DeclarativeEffect を持つ不可視の置物として戦闘開始時に自動注入（`buildLeaderPassive` の相似形。エンジン変更ほぼゼロ） | 毎ターン氷壁+1、戦闘開始時ドロー+2 |
| B. ラン定数型 | RunState のフィールドを取得時に書き換え | 最大HP+8、勝利時回復+5 |
| C. ルール改変型 | エンジンのフラグを参照する少数精鋭 | **伏せ同時2枚**（確定済みルール表「伏せ枚数（レリック拡張余地）」の回収） |

- データは `data/relics.json`（id/name/sprite/description/カテゴリ/効果）
- 新トリガーは `onCombatStart` のみ追加（既存の onTurnStart/onAttacked 等に相乗り）
- UI：トップバーにレリックアイコン列＋ホバーで説明（キーワード吹き出しの流用）

| レリック | 効果 | カテゴリ | 狙い |
|---|---|---|---|
| 二の符の帯 | **伏せを同時2枚まで置ける** | C | 看板レリック。独自コア（伏せ）を直接拡張。ブラフ×本命の二重化 |
| 茨の冠 | 被攻撃後、攻撃してきた敵に3ダメージ | A | 定番。成長と好相性 |

| 氷の護符 | 毎ターン開始時、氷壁+1 | A | 青シナジー。ラン消耗を緩和 |
| 賢者の巻物 | 戦闘開始時、2枚ドロー | A | 汎用。初手の再現性 |
| 霊気の管 | 戦闘開始時、霊気+2 | A | パーミッション支援 |
| 韋駄天の帯 | 毎ターン開始時、勢い+1 | A | トランプル支援 |
| 鉄の心臓 | 最大HP+8（取得時） | B | 汎用。焚き火の回復と直接比較させる誘惑枠 |

パワー指針：1個 ≈ カード1.5〜2枚分の価値（焚き火回復＝最大HP30%と釣り合う水準）。simで検証。

## 5. sim ボット方針

- パッシブ効果はボット変更不要（状態に乗るだけ）
- 焚き火の選択ポリシー：HPが50%未満なら回復、以上ならレリック（先頭を取得）
- 検証観点：レリック導入後の走破率が帯（8〜15%）を超えないか／「二の符の帯」の発動率変化

## 6. テスト方針（仕様＝テスト）

- 取得：焚き火でレリック選択→回復なし＋所持に追加／回復選択→従来通り
- A型：注入された置物がリーダーパッシブと共存して発火する
- C型：二の符の帯で2枚目が伏せられる／未所持では従来通り1枚制限
- 決定論：同シード＝同レリック候補列
